## 1. Flow Overview

The student club records members, events, budgets, expenses and income in Data Fabric. This flow approves a new expense: it reads the submitting member and the budget line, applies the approval rule (cost within remaining budget, member holds a position), and updates the expense's `approved` field.

### In Scope
- Expense approval decision and write-back.

### Out of Scope
- Event planning, income tracking, member onboarding.

### Assumptions
- All eight club record types are Native Data Fabric entities created by this solution in the `Shared` folder before the flow is published.

## 2. Flow Diagram

```text
start (record-created: Expense) → lookup-member (read Member) → lookup-budget (read Budget) → check-approval (if) → update-expense (update Expense) → end
```

## 3. Nodes Inventory

| # | Node Key | Node Type | Description | Inputs | Outputs | Notes |
|---|---|---|---|---|---|---|
| 1 | `start` | Trigger | New expense record created | — | `expense` | Trigger type: EVENT — Data Fabric `record-created`, object `Expense` |
| 2 | `lookup-member` | Data Fabric read | Read the submitting member | `expense.link_to_member` | `member` | `dataFabricRead({ entity: 'Member', filters: [{ field: 'member_id', value: expense.link_to_member }] })` |
| 3 | `lookup-budget` | Data Fabric read | Read the budget line | `expense.link_to_budget` | `budget` | `dataFabricRead({ entity: 'Budget', filters: [{ field: 'budget_id', value: expense.link_to_budget }] })` |
| 4 | `check-approval` | Logic (if) | cost ≤ budget.remaining AND member.position is not empty | `expense`, `member`, `budget` | `approved` | — |
| 5 | `update-expense` | Data Fabric update | Write the decision | `expense.Id`, `approved` | — | `dataFabricUpdate({ entity: 'Expense', recordId: expense.Id, fields: { approved } })` |
| 6 | `end` | End | — | — | — | — |
