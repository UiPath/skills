## 1. Process Overview

Operations collects customer address changes in the "Pending" sheet of the address-change workbook on the operations share, around 200 rows a day. Every weekday at 07:00 the automation reads the sheet and updates each customer's address in the Dynamics 365 web client, then emails the requester the change number. Operations wants the status of every row of the day and a summary when the run ends.

## 2. Process Map

1. Read the Pending sheet (07:00, weekdays).
2. For each row: open the customer in Dynamics 365, replace the address, save, read back the change number.
3. Email the requester the change number.
4. Mail operations the run summary.

## 3. Detailed Process Steps

| Step | Action | Application | Expected result |
|---|---|---|---|
| 3.1 | Read every row of the "Pending" sheet: customer number, new street address, postcode, city, country, requester email | Excel workbook | One row per address change |
| 3.2 | Sign in to the Dynamics 365 web client with the CRM robot account | Dynamics 365 | Home page |
| 3.3 | Open the customer by customer number | Dynamics 365 | Customer record open |
| 3.4 | Replace street address, postcode, city and country; save | Dynamics 365 | Record saved |
| 3.5 | Read back the change number shown after saving | Dynamics 365 | Change number |
| 3.6 | Email the requester the change number | Outlook | Mail sent |
| 3.7 | Write the row's status (Done, Rejected, Failed) and reason back to the sheet | Excel workbook | Status column filled |
| 3.8 | Mail operations a summary: rows taken, done, rejected, failed | Outlook | Summary mail |

## 4. Business Rules

| ID | Rule |
|---|---|
| BR-1 | A row whose customer number is unknown in Dynamics 365 is rejected: email the requester the reason; never retried. |
| BR-2 | A row whose postcode fails the country's postcode format is rejected: email the requester the reason; never retried. |

## 5. Data Definitions

| Field | Type | Source |
|---|---|---|
| CustomerNumber | Text | Pending sheet |
| Street, Postcode, City, Country | Text | Pending sheet |
| RequesterEmail | Text | Pending sheet |
| ChangeNumber | Text | Dynamics 365 after saving |

## 7. Exception Handling

| ID | Exception | Handling |
|---|---|---|
| BE-1 | Unknown customer number (BR-1) | Business exception: row Rejected, requester emailed |
| BE-2 | Invalid postcode (BR-2) | Business exception: row Rejected, requester emailed |

## 8. Error Handling

| ID | Error | Handling |
|---|---|---|
| SE-1 | Web client timeout or lost session | System exception: close and reopen Dynamics 365, retry the row 2 times [DEFAULT], then row Failed with the reason; the run stops after 3 consecutive system exceptions [DEFAULT] |

## 10. Master Project Architecture

| # | Project Name | Role | Framework | Input Queue | Output Queue |
|---|---|---|---|---|---|
| 1 | `CustomerAddressSync_Dispatcher` | Read the Pending sheet and add one queue item per row | Sequence | — | `CustomerAddressSync_Rows` |
| 2 | `CustomerAddressSync_Performer` | Update one customer per queue item, on two robots | REFramework | `CustomerAddressSync_Rows` | — |

## 11. Project Structure

Dispatcher: `Main.xaml` reads the sheet and adds the queue items with the row number as unique reference. Performer: REFramework with `Process.xaml` running steps 3.3–3.7 per transaction.

## 12. Queue Architecture

| Queue | Unique reference | Max retries | Purpose |
|---|---|---|---|
| `CustomerAddressSync_Rows` | business date + row number | 2 [DEFAULT] | One item per Pending row |

Automation Cloud, folder `Operations/CRM`. Dispatcher on a time trigger at 07:00 on weekdays; Performer on a queue trigger, two unattended robots.

## 17. Testing Strategy

| # | Scenario | Expected |
|---|---|---|
| T1 | A valid row | Address updated, change number mailed to the requester, row Done |
| T2 | Unknown customer number | Row Rejected, requester emailed the reason, no retry |
| T3 | Postcode in the wrong format for its country | Row Rejected, requester emailed the reason, no retry |
| T4 | Web client times out once | Row retried and Done |
| T5 | Three consecutive lost sessions | Run stops, rows Failed with the reason |
| T6 | End of run | Operations receives the summary with the four counts |
