## Recommended Scope

**Recommendation:** SINGLE_PRODUCT(Case Management)
**Delivery model:** cloud
**Blocked by platform:** none
**Need profile:** Track a supplier application through intake, buyer review, compliance/risk review, and setup, to onboarding, rejection, or withdrawal, against a 15-business-day SLA with per-phase targets.

### Case-Level SLA Escalation Rules

**Design Rationale:** The overall 15-business-day target is a case-wide health signal. At 70% (the source's stated threshold for every phase) the case just gets flagged for visibility. A full breach is a "start-task" response — a Procurement Director Post-Mortem Review task, placed once on each of the three mutually-exclusive wrap-up stages (Onboarded / Rejected / Withdrawn) so it exists no matter which outcome the case reaches — rather than a simple notify, per the source's "gets a task to review what went wrong before the application closes."

| SLA Status | Threshold | Action | Display Name |
|------------|-----------|--------|--------------|
| At-Risk | 70% of SLA duration | Notify: Procurement Operations Lead | Application Resolution SLA at risk |
| Breached | 100% of SLA duration | Notify: Procurement Director | Application Resolution SLA breached |

### Stage 1: Checking the Application (`checking`)

**Type:** Stage
**Stage Kind:** primary
**Design Rationale:** First gate before anyone reviews the application in depth; also the return point when the buyer sends it back for corrections, so it re-runs the same checks on resubmission.
**Description:** A once-over — validate the application's own details, pull up company records (duplicate check, sanctions prescreen, buyer lookup), and optionally flag anything odd in the offering description vs. the selected category.

## Non-Functional Requirements

| Dimension | Requirement / Design decision |
|---|---|
| Security | Sanctions/watchlist and financial documents (bank details, tax forms) are sensitive; least-privilege access to Action Apps and connector connections; PII limited to contact name/email. |
| Performance | Volume unspecified by the source; connector activities and agent calls run per-application, not in bulk. |
| Scalability | No stated concurrent-application volume; design assumes moderate throughput typical of a supplier-application pipeline. |
| Availability / Resilience | Connector activities should be idempotent on retry (e.g., ERP record creation); SLA timers persist across restarts by platform default. |
| Logging & Monitoring | SLA at-risk/breach escalations, and Log Rejection/Withdrawal for Audit tasks, provide the audit trail the source requires. |
| Compliance | Sanctions/watchlist screening and compliance/risk review are explicit regulatory-adjacent controls; audit log captures who rejected, why, and when. |

## Testing Strategy

| Scenario | Setup | Expected Outcome |
|---|---|---|
| Happy path | Valid application, spend < $500,000, no reference check or legal opinion requested | Case reaches Onboarded; welcome message sent, supplier recorded in register |
| High-value sign-off | Application with expectedAnnualSpend >= 500000 | Compliance Decision task only becomes available after Procurement Director Sign-off completes |
| Buyer decline | Buyer Decision = Decline | Case routes to Rejected; rejection notice and audit log recorded |
| Compliance rejection | Compliance Decision = Reject | Case routes to Rejected |
| Bank verification failure | Create Supplier Record in ERP returns bankDetailsVerified = false | Supplier Setup exits to Rejected instead of waiting on portal access |
| Send back for corrections | Buyer Decision = SendBack | Case re-enters Checking the Application; validation checks re-run |
| Withdrawal mid-review | Supplier withdrawal event fires while in Checking, Buyer Review, or Compliance and Risk Review | Case interrupts into Withdrawn regardless of origin stage |
| Phase SLA breach | Any primary or wrap-up stage exceeds its target | Escalation task created for Procurement Operations Lead; supplier delay notice sent |
| Case-level SLA breach | Overall 15-business-day target exceeded | Procurement Director Post-Mortem Review task appears in whichever wrap-up stage the case reaches |
| Optional extras | Order Reference Check and Request Legal Counsel Opinion invoked | Findings/opinion recorded and visible to the next decision-maker |
