## Testing Strategy

| Scenario | Setup | Expected Outcome |
|---|---|---|
| Happy path approved | Complete evidence, clear due diligence, reconciled analysis, approved lines, successful Salesforce and LAMS responses | Case reaches matched activation and closes with complete lineage. |
| Happy path declined | Complete evidence, human Credit decline, no approved lines | Final report publishes, Salesforce records the decline, no LAMS activation occurs, and the Case closes through the approved alternate outcome. |
| Incomplete evidence | Missing, unreadable, stale, duplicate, or contradictory evidence | Readiness fails, targeted request is created, the Case waits, and no decision package is released. |
| Low extraction confidence | Extraction result below the approved threshold | Evidence is routed to human review or re-scan; no value is silently accepted. |
| Compliance finding | Active or ambiguous KYRA/adverse finding | Specialist or Compliance action is created and the normal path is suspended. |
| Financial discrepancy | Declared values conflict with external or internal debt | Reconciliation exception and clarification route are created; any adjustment requires rationale and review. |
| Banking challenge | New mitigant or evidence after preliminary report | Decision version is updated and impacted analysis or approval is repeated as required. |
| Approval return | Credit approver returns the package for analysis or clarification | Case routes to the impacted stage with the return reason and prior version retained. |
| Connector timeout | Salesforce, source system, customer channel, or LAMS operation times out | Retry policy is applied; unresolved failure creates an exception and prevents false completion. |
| LAMS mismatch | Returned line, amount, or terms differ from the approved decision | Activation reconciliation task remains open; Case cannot close until matched or authorized alternate disposition. |
| Duplicate event | Salesforce sends the same proposal event more than once | Idempotency prevents duplicate Case creation or links the event to the existing Case. |
| Unauthorized action | User lacks the required role for approval, compliance, or activation | Action is blocked and the event is audited. |
| End-to-end revalidation | Existing customer with updated evidence and prior decision history | New evaluation version is linked to prior evidence without overwriting historical decisions. |
