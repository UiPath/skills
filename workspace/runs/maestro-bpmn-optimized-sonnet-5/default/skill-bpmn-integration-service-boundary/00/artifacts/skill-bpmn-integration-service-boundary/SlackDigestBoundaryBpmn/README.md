# SlackDigestBoundaryBpmn (local draft)

Local Maestro Process Orchestration draft. **Not uploaded, published, deployed,
debugged, or run.** This project only exists as local BPMN source plus
untouched scaffold metadata from `uip maestro bpmn init`.

## Process

```
manual start -> prepare digest (script task) -> send Slack digest (draft Integration
Service boundary) -> end
```

- `Event_start` (`core.trigger.manual`) — manual entry point,
  `uipath:entryPointId` = `2e6c93b9-8c14-4c15-a0e8-a1567c545abe`.
- `Task_PrepareDigest` — `bpmn:scriptTask` (`BPMN.ScriptTask`, Jint). Builds a
  placeholder digest string and writes it to root variable `Var_DigestText`.
- `Task_SendSlackDigest` — `bpmn:sendTask` wrapping registry type
  `Intsvc.ActivityExecution` (Integration Service "Execute connector
  activity"). **Draft only** — see blockers below. Output is mapped to root
  variable `Var_SlackResponse`.
- `Event_end` — end event.

Root variables (`uipath:variables`, process-scoped):

| id | name | type | purpose |
| --- | --- | --- | --- |
| `Var_DigestText` | DigestText | string | digest body produced by the script task |
| `Var_SlackResponse` | SlackResponse | json | Slack connector response (empty until enriched/run) |

## Why the Slack step is a draft boundary, not an executable node

`Intsvc.ActivityExecution` is the correct, registry-supported BPMN wrapper for
Integration Service connector intent (`bpmn:sendTask` + `uipath:activity` /
`uipath:type value="Intsvc.ActivityExecution"`). It was authored from the live
registry template (`uip maestro bpmn registry get Intsvc.ActivityExecution`),
not hand-written. However, this template is a shell: every context field that
makes it runnable is blank in the source, and no connection, connector
resource key, folder key, tenant URL, or schema has been invented to fill it.

`uip maestro bpmn validate SlackDigestBoundaryBpmn.bpmn` confirms this
intentionally-incomplete state — it reports 6 errors, all pointing at the same
draft node:

```
Integration Service activity is missing required context input "connectorKey".
Integration Service activity is missing required context input "operation".
Integration Service activity is missing required context input "objectName".
Integration Service activity is missing required context input "method".
Integration Service activity is missing required context input "path".
EMPTY_REQUIRED_FIELD: The field 'connectorKey' in node '...' is required but has no value.
```

These are expected for a draft node and are the exact blockers this README
tracks.

## CLI-owned enrichment blockers (must be resolved before upload or run)

The following are **not authored locally** and must be supplied by the
UiPath CLI / Integration Service tooling before this project can be uploaded,
packaged, or run:

1. **Connector operation metadata** — `connectorKey`, `operation`,
   `objectName`, `method`, `path` on `Task_SendSlackDigest`. Resolve with:
   ```
   uip is activities list uipath-salesforce-slack --output json
   ```
   then fill the chosen activity's `Name` -> `operation`, `ObjectName` ->
   `objectName`, `MethodName` -> `method`, plus the request `path` returned by
   resource metadata for that operation.
2. **Connection binding** — a live Slack connection id resolved with:
   ```
   uip is connections list --all-folders --output json
   ```
   then wired through a process-level `<uipath:bindings>` entry
   (`resource="Connection"`, `propertyAttribute="ConnectionId"`) and referenced
   from the activity context as `=bindings.<bindingId>`. No connection id is
   present in this source.
3. **Dynamic schemas** — the request/response JSON schema for the selected
   Slack operation, generated by re-running:
   ```
   uip maestro bpmn registry get Intsvc.ActivityExecution --connection-id <id> --object-name <object> --output json
   ```
   which returns an `ISEnrichment` block with the live field metadata. This
   BPMN was authored from the unenriched template only, so no request/response
   fields have been added yet.
4. **Generated outputs** — the `response` output mapping on
   `Task_SendSlackDigest` is a placeholder (`type="jsonSchema"`, no schema
   body). Concrete output fields are produced by the enrichment call above.
5. **`bindings_v2.json`** — currently the empty scaffold
   (`{"version": "2.0", "resources": []}`) written by `uip maestro bpmn init`.
   It must be regenerated/enriched by the CLI once the connection binding and
   connector metadata above are resolved; do not hand-edit it.
6. **Package metadata** — `entry-points.json`, `operate.json`,
   `package-descriptor.json` are the untouched local scaffold from
   `uip maestro bpmn init`. Any packaging step
   (`uip maestro bpmn update-metadata` / `uip maestro bpmn pack`) must be run
   by the CLI, not hand-authored, once the BPMN source above is fully
   enriched.

Until all six are resolved through the CLI, `Task_SendSlackDigest` stays in
**draft** status (BPMN shape/intent present, enrichment missing) — not
**executable**, **mock**, or **blocked**-and-ignorable. Do not fill any of the
above with guessed or invented values.
