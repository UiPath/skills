**Node type:** `core.action.http.v2`
**Display name:** HTTP Request
**Category:** `data-operations`
**Owner:** CLI-owned (uses `inputs.detail` envelope + `bindings[]`) — authored with `uip maestro flow node add` + `uip maestro flow node configure`

**Ports:**
- Input: `input` (left)
- Outputs: `default` (right), plus dynamic `branch-{item.id}` branches, and `error` (visible when `errorHandlingEnabled`)

**Key inputs (from `inputDefinition`):**
| Field | Type | Default | Notes |
|---|---|---|---|
| `branches` | array | `[]` | Named status-code branches for routing |
| `timeout` | string (ISO 8601) | `PT15M` | e.g. `PT30S`, `PT1H` |
| `retryCount` | number | `0` | Automatic retries |

The actual HTTP configuration (method, URL, headers, body, auth mode) lives inside `inputs.detail` as a `=jsonString:…` envelope — set via `node configure`, never hand-authored.

**Output variable:** `$vars.<nodeId>.output` — the full HTTP response object (status, headers, body)
**Error variable:** `$vars.<nodeId>.error` — `{ code, message, detail, category, status }`

> Note: `core.action.http` (no version suffix) also exists in the registry but is the older v1 — always use `core.action.http.v2`.

---

### Script node — `core.action.script` (v1.1)

**Node type:** `core.action.script`
**Display name:** Script
**Category:** `data-operations`
**Owner:** User-owned — authored directly in the `.flow` JSON with `Edit`

**Ports:**
- Input: `input` (left)
- Outputs: `success` (right), `error` (visible when `errorHandlingEnabled`)

**Key inputs:**
| Field | Type | Required | Notes |
|---|---|---|---|
| `script` | string | yes | Inline JavaScript; minimum 1 char |

The script must return a value — it becomes `output` via `=result.response`.

**Output variable:** `$vars.<nodeId>.output` — whatever the script returns (type: `any`)
**Error variable:** `$vars.<nodeId>.error` — same error shape as above

**Runtime:** `clientScript` (runs in the BPMN engine's JS sandbox, not Node.js)

## How they connect for your use case

```
[Trigger] → [core.action.http.v2] --default--> [core.action.script] --success--> [End]
                                   └--error--> (optional error path)
```

- Wire the HTTP node's `default` port → script node's `input` port
- Inside the script, access the response body as `$vars.<httpNodeId>.output.body` (or `.statusCode`, `.headers`)
- The script returns its processed result, available downstream as `$vars.<scriptNodeId>.output`

When you're ready to build, the HTTP node requires `uip maestro flow node add` + `uip maestro flow node configure` (CLI-owned), while the script node and all wiring go directly into the `.flow` JSON (user-owned).
