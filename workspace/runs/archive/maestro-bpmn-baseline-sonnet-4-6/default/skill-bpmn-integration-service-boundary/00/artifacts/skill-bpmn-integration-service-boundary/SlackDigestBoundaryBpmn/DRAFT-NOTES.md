## CLI-owned enrichment blockers

The **Send Slack Digest** node (`Task_SendSlack`) is an Integration Service
activity boundary.  The following items are **CLI-owned** and must **not** be
hand-authored.  They are represented as `&lt;CLI_SUPPLIED_…&gt;` placeholder
strings in the BPMN source.

### 1. Connector key

The `connectorKey` context field must be resolved by searching the live
registry — not guessed from the brand name:

```bash
uip maestro bpmn registry search slack --output json
```

Pick the exact `ExtensionType` string (for example `uipath.slack`) returned by
the search.  Do not fabricate a connector resource key.

### 2. Connection binding

A live Slack connection must exist in the tenant before enrichment.  List all
connections across every folder:

```bash
uip is connections list --all-folders --output json
```

The `ConnectionId` (a GUID) of the chosen connection populates the
`default` attribute of `Binding_SlackConnection` in the BPMN
`<uipath:bindings>` block.  This is the **connection binding** and it is
entirely CLI-owned — do not invent a GUID.

The `resourceKey` attribute on both binding elements
(`Binding_SlackConnection` and `Binding_SlackFolder`) is also CLI-owned:
it is the connector's resource key resolved by the CLI enrichment step from
the chosen connection's connector metadata.  The placeholder
`&lt;CLI_SUPPLIED_CONNECTOR_RESOURCE_KEY&gt;` in the BPMN source must be
replaced with the real value from the enrichment output.

### 3. Folder key

The folder that owns the connection supplies the `folderKey` binding
(`Binding_SlackFolder`).  This value also comes from the `uip is connections
list --all-folders` output and is CLI-owned.

### 4. Connector operation metadata

Run the full enrichment command to retrieve the connector's activity catalog:

```bash
uip maestro bpmn registry get Intsvc.ActivityExecution \
    --connection-id <CONNECTION_ID> \
    --object-name <OBJECT_NAME> \
    --output json
```

The `ISEnrichment` block in the response supplies:

- `operation` — the catalog `Name` used as the runtime operation identifier
- `objectName` — the object (for example `chat.message`)
- `method` — HTTP method for the underlying request
- `path` — request path returned by resource metadata

All four are CLI-owned.  The placeholders in the BPMN source
(`&lt;CLI_SUPPLIED_OPERATION&gt;`, `&lt;CLI_SUPPLIED_OBJECT_NAME&gt;`,
`&lt;CLI_SUPPLIED_METHOD&gt;`, `&lt;CLI_SUPPLIED_PATH&gt;`) must be replaced
with the values from this command's output.

### 5. Dynamic schemas

The request body field names, types, and their `target` attributes (path,
query, body) are **generated dynamically** from the `ISEnrichment` response.
The stub input element in the BPMN source:

```xml
<uipath:input name="&lt;CLI_SUPPLIED_FIELD_NAME&gt;" type="string" target="body"
              value="=vars.Var_DigestText" />
```

must be replaced with one `<uipath:input>` per request field discovered from
the enrichment.  The `value` mapping from `Var_DigestText` should be adjusted
once the real field name (for example `text`) is confirmed from the schema.

The output variable (`Var_SlackResult`) captures a raw JSON blob until the
real `jsonSchema` for the response is generated by the CLI and written into
`bindings_v2.json`.

### 6. `bindings_v2.json`

The runtime binding manifest is **generated by the CLI** from the BPMN source
and enrichment metadata:

```bash
uip maestro bpmn generate-bindings SlackDigestBoundaryBpmn.bpmn --output json
```

Do not hand-author `bindings_v2.json`.

### 7. Generated outputs (`entry-points.json`, `operate.json`, `package-descriptor.json`)

These package-metadata files are **CLI-owned** and must be generated (not
hand-authored) before the project can be packed or uploaded:

```bash
uip maestro bpmn init SlackDigestBoundaryBpmn  # or equivalent scaffold
uip maestro bpmn validate SlackDigestBoundaryBpmn.bpmn --output json
uip maestro bpmn pack SlackDigestBoundaryBpmn <OutputDir> --output json
```

None of these files appear in this local draft project.  They are omitted
intentionally — packing will fail until enrichment is complete and all
CLI-owned blockers above are resolved.

### 8. Package metadata

The `project.uiproj` in this draft does **not** contain generated package
identifiers, version hashes, or publish metadata.  Those fields are populated
by the CLI packaging and publishing pipeline and must not be invented locally.
