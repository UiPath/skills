# SlackDigestBoundaryBpmn — Draft Notes

**Status: LOCAL DRAFT — NOT READY FOR UPLOAD, PUBLISH, OR RUN**

This project is a structural BPMN draft. The process shape, variable declarations,
sequence flows, and diagram geometry are authored. The Slack Integration Service
step (`Task_SendSlack`, type `Intsvc.ActivityExecution`) is present as an
**executable boundary**: the BPMN shape, variable wiring, and routing are in place,
but the node cannot execute until every CLI-owned enrichment item below is resolved.

---

## CLI-owned enrichment blockers

The following items **must** be resolved via the UiPath CLI before this project can
be packaged, uploaded, or run. None of them can be safely hand-authored — they
require live discovery commands.

### 1. Connection ID and binding (`Binding_SlackConn`)

**Blocker:** The `<uipath:binding default="DRAFT_CONNECTION_ID">` in the process
`<uipath:bindings>` block holds a placeholder. The real Slack connection ID must be
discovered and substituted.

**CLI steps:**

```
uip is connections list --all-folders --output json
```

Find the Slack connection entry. Copy its `Id` value. Replace `DRAFT_CONNECTION_ID`
in the `<uipath:binding>` element with that value.

---

### 2. Connector operation metadata (activity, connectorKey, method, path)

**Blocker:** The `Task_SendSlack` context inputs hold draft tokens:
`DRAFT_ACTIVITY`, `DRAFT_CONNECTOR_KEY`, `DRAFT_METHOD`, `DRAFT_PATH`.

These values come from the `ISEnrichment` block returned by:

```
uip maestro bpmn registry get Intsvc.ActivityExecution \
    --connection-id <RESOLVED_CONNECTION_ID> \
    --object-name <OBJECT_NAME> \
    --output json
```

Copy the `activity`, `connectorKey`, `method`, and `path` values from the
`ISEnrichment` response into the matching `<uipath:input>` elements.

---

### 3. Folder key (`DRAFT_FOLDER_KEY`)

**Blocker:** The `folderKey` context input holds `DRAFT_FOLDER_KEY`. Discover the
correct Orchestrator folder:

```
uip or folders list --output json
```

Replace `DRAFT_FOLDER_KEY` with the resolved folder key or path.

---

### 4. Dynamic request body schema

**Blocker:** The `<uipath:input name="body">` CDATA in `Task_SendSlack` is an
intent-only stub (`channel` and `text`). The authoritative Slack connector request
schema is dynamic and generated by the CLI enrichment step in blocker 2 above
(`ISEnrichment` in the `registry get` response). Replace the body CDATA with the
schema-correct payload after enrichment.

---

### 5. `bindings_v2.json` — connector resource entry

**Blocker:** Running `scripts/scaffold_metadata.py` generates a `bindings_v2.json`
with an empty `resources` array. For `Intsvc.*` connector nodes the CLI must
populate that array with the resolved connector resource entry before packaging.

The scaffold script is safe to run for other metadata files (`project.uiproj`,
`operate.json`, `entry-points.json`, `package-descriptor.json`), but
`bindings_v2.json` **must not** be used as-is for upload or run.

---

### 6. Package metadata (all five files)

**Blocker:** None of the five package metadata files (`project.uiproj`,
`operate.json`, `entry-points.json`, `bindings_v2.json`, `package-descriptor.json`)
exist yet. Generate them only after blockers 1–4 are resolved:

```
pip install defusedxml
python3 scripts/scaffold_metadata.py \
    --bpmn SlackDigestBoundaryBpmn/SlackDigestBoundaryBpmn.bpmn \
    --out-dir SlackDigestBoundaryBpmn/
```

Then enrich `bindings_v2.json` with the connector resource entry (blocker 5), run
the drift check, and only then package:

```
python3 scripts/check_metadata_drift.py \
    --bpmn SlackDigestBoundaryBpmn/SlackDigestBoundaryBpmn.bpmn \
    --project-dir SlackDigestBoundaryBpmn/
uip maestro bpmn pack --project-dir SlackDigestBoundaryBpmn/
```
