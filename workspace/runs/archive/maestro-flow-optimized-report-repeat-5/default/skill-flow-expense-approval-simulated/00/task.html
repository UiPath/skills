### What it does
An expense report is submitted (manual trigger with employee + amount data), a manager gets an inline review form to **Approve** or **Reject**, and the decision is logged. Two clean terminal paths: one for approval, one for rejection.

### Flow diagram

```mermaid

    prepareContext[Prepare Context]
    managerReview[Manager Review HITL]
    decideOutcome{Approved}
    logApproval[Log Approval]
    logRejection[Log Rejection]
    doneApproved(Done Approved)
    doneRejected(Done Rejected)
    trigger -->|output| prepareContext
    prepareContext -->|success| managerReview
    prepareContext -->|error| doneRejected
    managerReview -->|outcome-completed| decideOutcome
    decideOutcome -->|true| logApproval
    decideOutcome -->|false| logRejection
    logApproval -->|success| doneApproved
    logRejection -->|success| doneRejected
```

### Nodes
| Node | Type | Role |
|---|---|---|
| Manual Trigger | `core.trigger.manual` | Entry point; carries expense data as flow inputs |
| Prepare Context | `core.action.script` | Formats the expense data into a readable summary for the manager |
| Manager Review | `uipath.human-in-the-loop.quick-form` | Manager sees employee name, description, amount — clicks **Approve** or **Reject** |
| Approved? | `core.logic.decision` | Routes based on manager's choice |
| Log Approval / Log Rejection | `core.action.script` × 2 | Builds a structured log entry `{ employee, amount, decision, comments, timestamp }` |
| Done (×2) | `core.control.end` | Terminal nodes for each path |

`employeeId`, `employeeName`, `expenseDescription`, `amount (number)`

`approvalLog` — an object with the full decision record
