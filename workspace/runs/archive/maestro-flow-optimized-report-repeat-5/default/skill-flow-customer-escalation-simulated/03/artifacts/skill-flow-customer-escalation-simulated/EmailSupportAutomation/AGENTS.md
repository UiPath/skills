## Architecture

- **Pattern**: Main orchestrates two sequential sub-workflow invocations per email (Triage → Process)
- **Data flow**: IMAP messages returned as `Object`; fields extracted by reflection via `InvokeCode`; typed strings passed as arguments to sub-workflows
- **Execution flow**: Log start → GetIMAPMailMessages (TryCatch, fatal on failure) → If emails exist → ForEach email → extract fields → InvokeWorkflowFile TriageEmail → InvokeWorkflowFile ProcessEmail → increment counter → Log completion
- **Triage categories**: `Urgent` (High priority), `Billing` (Normal priority), `Technical` (Normal priority), `General` (default, Normal priority)
- **Queue item fields**: `From`, `Subject`, `Category`, `Priority`, `ReceivedAt`; reference key: `{sender}|{yyyyMMddHHmmss}`
- **External integrations**: IMAP inbox (inbound read), SMTP (outbound auto-reply), UiPath Orchestrator Queues (routing)
- **Config**: All connection settings (IMAP server/port/credentials, SMTP server/port, queue name) are local variables in Main.xaml — comments note these should be replaced with Orchestrator Assets in production
