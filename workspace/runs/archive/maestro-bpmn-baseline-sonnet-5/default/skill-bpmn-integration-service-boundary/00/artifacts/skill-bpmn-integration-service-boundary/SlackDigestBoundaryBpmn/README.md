# SlackDigestBoundaryBpmn (local draft)

Local Maestro Process Orchestration project. Authored offline; **not**
uploaded, published, deployed, debugged, or run.

## Process

`manual start` → `Prepare digest` (script task) → `Send Slack digest`
(Integration Service draft boundary) → `end`

- `Event_start` — `core.trigger.manual` entry point (`uipath:entryPointId`
  `01df750e-11c5-4df8-96c1-ecdfd8fa0aab`).
- `Task_PrepareDigest` — `bpmn:scriptTask` (`BPMN.ScriptTask`, Jint). Builds
  the digest text locally and writes it to the root variable
  `Var_DigestMessage`.
- `Task_SendSlackDigest` — `bpmn:sendTask` using the registry extension type
  `Intsvc.ActivityExecution` (connector: Slack, `connectorKey`
  `uipath-salesforce-slack`; selected catalog operation `SendMessage` /
  `send_message_to_channel_v2`). This is a **draft executable boundary
  only** — see blockers below.
- `Event_end` — process end event.

Root variables: `Var_DigestMessage` (string, produced by the script task),
`Var_SlackSendResult` (object, intended to hold the connector response once
enriched).

Root bindings: `Binding_SlackConnection` — a `resource="Connection"` binding
with `propertyAttribute="ConnectionId"`. Its `resourceKey` is the literal
placeholder `<CONNECTION_ID_PENDING_CLI_ENRICHMENT>` — **not** a real
connection id. No connection id, folder key, tenant URL, or connector
resource key was invented for this draft.

## Why this is a draft, not an executable Slack integration

The `Send Slack digest` node uses the correct, registry-supported BPMN
wrapper for Integration Service intent (`Intsvc.ActivityExecution` on
`bpmn:sendTask`) so the shape imports and renders correctly on the Maestro
canvas. It intentionally stops there. It represents *intent* — "call the
Slack connector's send-message operation with the prepared digest" — and
nothing beyond intent is authored by hand.

## CLI-owned enrichment blockers (must be resolved before upload or run)

The following are **CLI-owned enrichment**, not authored in this BPMN
source, and each one blocks upload, publish, deploy, debug, or run of this
project until resolved through the UiPath CLI:

1. **Connector operation metadata** — the `operation` (`SendMessage`),
   `objectName` (`send_message_to_channel_v2`), `method` (`POST`), and
   `path` context fields were only discovered from the connector's activity
   *catalog* (`uip is activities list uipath-salesforce-slack`). The `path`
   value in this file is the literal placeholder
   `<PATH_PENDING_CLI_ENRICHMENT>` — the real request path, parameters, and
   field catalog for this operation must still be pulled from
   `uip maestro bpmn registry get Intsvc.ActivityExecution --connection-id
   <id> --object-name send_message_to_channel_v2` before this node is
   runnable.
2. **Connection binding** — `Binding_SlackConnection.resourceKey` must be
   replaced with a real Integration Service connection id, resolved via
   `uip is connections list --all-folders` and written through the same
   `registry get --connection-id <id> --object-name
   send_message_to_channel_v2` enrichment call. The placeholder value in
   this file is not usable at runtime.
3. **Dynamic schemas** — the request body fields and response shape for the
   `SendMessage` (`send_message_to_channel_v2`) operation are dynamic and
   come from the connector's live field metadata (`ISEnrichment` block
   returned by `registry get` with `--connection-id`/`--object-name`). No
   request/response schema has been authored here.
4. **Generated outputs** — the `Var_SlackSendResult` output mapping
   currently targets a generic `object` variable with no field-level shape.
   The real output fields are only known once CLI enrichment generates the
   connector's output schema.
5. **`bindings_v2.json`** — the package binding resource for
   `Binding_SlackConnection` (and any folder-scoped binding, if the selected
   activity requires folder scoping) must be generated/enriched by the CLI.
   The current `bindings_v2.json` in this project directory is the
   unenriched scaffold and does not yet contain a resource entry for this
   connection.
6. **Package metadata** — `entry-points.json`, `operate.json`, and
   `package-descriptor.json` were generated by `uip maestro bpmn init` for
   the original single-entry-point scaffold. They have not been
   regenerated for the `Prepare digest` / `Send Slack digest` nodes added
   after init, and must be refreshed by the CLI (not hand-edited) once
   connector enrichment above is complete.

Until all six are resolved, this project's Integration Service step status
is **draft**: BPMN shape and intent are present; connector enrichment is
missing. Local validation (`uip maestro bpmn validate`) passes because it
checks structural/canvas rules, not connector runtime readiness — a passing
validation does not mean the Slack step is runnable.

## What was deliberately not invented

Per the authoring constraints for this draft, none of the following were
fabricated:

- Connection IDs
- Folder keys
- Tenant URLs
- Connector resource keys (beyond the public `connectorKey` value
  `uipath-salesforce-slack`, which identifies the connector itself, not a
  tenant resource)
- Generated/dynamic schemas
- Package metadata (`bindings_v2.json`, `entry-points.json`,
  `operate.json`, `package-descriptor.json` contents beyond the CLI's own
  `init` scaffold)

## Explicitly out of scope for this draft

This project was authored locally only. No upload, publish, deploy, debug,
or run action was taken or attempted against any UiPath tenant.
