### Filter tree (the core of this task)

Two AND-joined leaf conditions, matching the connector trigger's structured filter format exactly:

```json
{
  "groupOperator": 0,
  "index": 0,
  "filters": [
    {
      "id": "subject",
      "operator": "Contains",
      "value": { "value": "good day", "rawString": "\"good day\"", "isLiteral": true }
    },
    {
      "id": "fromAddress",
      "operator": "Equals",
      "value": { "value": "abc@xyz.com", "rawString": "\"abc@xyz.com\"", "isLiteral": true }
    }
  ]
}
```

- `groupOperator: 0` = **AND** — both conditions must match simultaneously.
- `"id": "subject"` / `"id": "fromAddress"` — field names from `filterFields.fields[].name` in the enriched registry response. The file notes that `fromAddress` is the expected name per the connector-trigger reference (the `impl.md` `filterFields` example shows exactly this name for Outlook). These **must be verified** against the live `registry get --connection-id` response before configure runs.
- The CLI **compiles** this tree into a JMESPath `filterExpression` automatically and writes both into the flow; you never pass `filterExpression` directly.
