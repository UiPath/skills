### How it works (architecture)
The node expands at compile-time into a **BPMN SubProcess** that contains:
1. A `StartEvent`
2. A `SendTask` (`Intsvc.UnifiedHttpRequest`) that calls the underlying **`uipath-uipath-http` Integration Service connector**
3. An optional `ExclusiveGateway` for response-code branching
4. `EndEvent` nodes per branch (including a `Default` and optional `Failure`)
5. A non-interrupting `BoundaryEvent` for error capture

### Inputs (`inputDefinition`)
| Property | Type | Default | Notes |
|---|---|---|---|
| `branches` | `array` of `{id, name, conditionExpression}` | `[]` | Conditional branches on response status/properties |
| `timeout` | ISO 8601 duration string | `"PT15M"` | Pattern validated; e.g. `PT1H`, `P1D` |
| `retryCount` | `number` | `0` | Auto-retries on failure |
| `detail` *(form only)* | DAP config | — | Connector/connection binding via UI component |

### Outputs
| Output var | Type | Source expression | Description |
|---|---|---|---|
| `output` | `object` | `=response` | Full HTTP response object |
| `error` | `object` | `=Error` | Error payload (fields: `code`, `message`, `detail`, `category`, `status`) |

### Output handles (right side)
- `branch-{item.id}` — one per conditional branch (dynamic)
- `default` — unconditional / fallthrough
- `error` — visible only when `errorHandlingEnabled` is true; max 1 connection

### Key binding requirement
Needs a **connection binding** for the `uipath-uipath-http` connector (Integration Service) and a `FolderKey` binding. The HTTP method, URL, headers, and body are configured through the embedded `dap-config` + `dap-http-toolbar` UI components.
