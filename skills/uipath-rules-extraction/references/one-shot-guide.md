# Quick Draft (IXP) Guide

Use only when the user picked `Quick draft (IXP)` in Framing (critical rule 19). The offer conditions and the typed-answer rule are in [phase-guide.md](phase-guide.md) (Framing). `<OUT_DIR>` is `<TEMP_DIR>/one-shot`.

1. **Ask for the profile once; its answers are the go-ahead.** IXP derives the inputs and structure itself, so these answers are all it takes. Use the Framing decision question as the query and show it in the question text; do not ask for it. One AskUserQuestion, at most three questions, then run right after it with no separate confirmation. State in the question text that answering starts a billed run, uploads the document to the chosen folder, and deletes the upload afterwards. Ask again only when an answer leaves a profile field missing or invalid. State the profile in one line before the run.
   - **Outcomes.** Each as `Label[:polarity[:operator]]`: polarity `positive`, `negative`, or `neutral`; operator `any`, `all`, or `first`; polarity defaults to `positive`; a label cannot contain `:`. Propose them from the request, including an outcome for insufficient information (critical rule 14), such as `Refer:neutral`.
   - **Score bands**, only when the decision is scored: `MIN-MAX=Outcome`, lowest first, inclusive integers, no gaps or overlaps, `5-` is the open top band; every band's outcome is an outcome label.
   - **Orchestrator folder.** The run needs `IXPModels.Create` there. Run `uip or folders list --output json`; propose the `Personal` folder as option 1, then the other `Standard` folders by `Path`. Never invent a folder key.

   Always send `--notes`: IXP is told only the outcome labels, so the notes are the one place it learns what an outcome means, and it emits a row for an outcome only when a rule in the policy votes for it. Write one line per outcome from the user's own answers, always including `<LABEL>: use when the information needed to decide is missing or unclear` for the insufficient-information outcome, plus any fact the user stated (jurisdiction, line of business, an assumption). Never put policy interpretation there. Keep the query at 2000 characters or fewer and the notes at 8000 or fewer.
2. **Create the project, then run the one command.** Create `<PROJECT_DIR>` as in Inputs and structure (critical rule 10); it stays empty of rows. Then run `one-shot.mjs` once. It checks the profile and login, runs IXP, writes the returned DMN over the project's `.dmn`, and runs `uip rules refresh` and `validate`. Do none of those steps by hand. It prints one JSON object; read stdout only.
   ```bash
   node "<SKILL_DIR>/scripts/one-shot.mjs" --project-dir "<PROJECT_DIR>" --file "<DOCUMENT_FILE>" --out "<OUT_DIR>" \
     --folder-key "<FOLDER_KEY>" --query "<QUESTION>" --outcome "<LABEL>:<POLARITY>:<OPERATOR>" --notes "<TEXT>"
   ```
   Add `--check` to validate the profile, login, and project without a run, one `--score-band "<MIN>-<MAX>=<LABEL>"` per band when they apply, and `--profile <NAME>` for a named `uip` login.
   - Exit 0, `status` `completed`: the DMN is written and valid.
   - Exit 1, `status` `completed-with-diagnostics`: the DMN is written but `validate` failed. Repair `diagnostics` in the written `.dmn` (critical rule 12).
   - Exit 1, `status` `error`: `stage` names where it stopped. A `run_id` in the result means a billed run had started: say so, and never start another. When `fallback` is `true`, follow step 4. When it is `false` (IXP rejected the profile or attachment), show the `error`, ask once whether to change the profile, and otherwise follow step 4.
   - Exit 2: a usage or project error. Fix what the `error` names and run `--check` again.
   - An expired or missing login: ask the user to run `! uip login`; never run it yourself.
3. **Finish, shortened.**
   - Run the sampled runs as in Finish step 5 ([phase-guide.md](phase-guide.md)), and the uipdm check when the uipath-rules skill documents one.
   - Read the written `.dmn`: the `inputData` names, the `allowedAnswers` of the `policy_decision` decision. Show the inputs and outcomes next to the Framing profile. A difference is a question to the user, never a silent edit.
   - **An empty `policy_decision` is not a defect.** IXP's DMN follows its own hit policy, so a sampled run that returns no outcome for the omitted-input set is how IXP reports insufficient information. Critical rule 14's default row does not apply to this DMN: add no row and no outcome to `policy_decision`, and tell the user what the result means for the consumer (the standard DMN meaning of the table's `hitPolicy`).
   - Repair only a FEEL evaluation error from a sampled run (critical rule 12), and only in the failing condition, as the smallest change that keeps its meaning; a missing list input must evaluate without an error and without becoming `met`. Write no XML comments (critical rule 7).
   - Skip `resolve-refs.mjs` and the clause-coverage check: the `uipdm:sourceRef` entries carry `page`, `blockId`, and `box`, with no quote, and no `document.md` was made.
   - The summary follows "State the limits" in [phase-guide.md](phase-guide.md), and adds: the review level `Quick draft (IXP)`, the profile used, that the rule was generated from the base document only and not checked clause by clause, what an empty result means for the consumer, which expression was repaired and that IXP wrote the original (when one was), and that no supporting document was applied.
   - Do not ask about, or offer, amendments or other documents. If the user brings one later, edit the `.dmn` directly (critical rule 10).
4. **Fall back.** Fall back when the script reports `fallback: true`, when `fallback` is `false` and the user declines to change the profile, when the user asks for the guided flow, or when login is missing and the user will not log in. Say in one sentence what failed (the `stage` and the `error`, with no token and no URL), and that the guided extraction continues at `Ask me only when unclear`; the user can change the level at the next checkpoint. Resume at Intake with the Framing answers and the outcomes the user gave; do not re-ask them. Never run IXP again for this request.
