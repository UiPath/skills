# Inline Agent in a Flow

Walkthrough for a low-code agent embedded directly inside a Maestro Flow. An inline agent is **authored in the `.flow`**: the agent node's `inputs` hold the agent's configuration, and every resource node wired to it holds that resource's configuration. The agent is published with the parent flow.

This file covers the **agent side** — what goes into the agent node's and its resource nodes' `inputs`, and the refresh / validate lifecycle. Flow-graph authoring (adding nodes, `definitions[]`, edges, variables, layout) is the `uipath-maestro-flow` skill's responsibility (Critical Rule 15).

## When to Use

- Agent is tightly coupled to this specific flow
- No need for separate versioning, evaluation, or reuse across flows
- Fastest to set up — no separate agent project required

## Standalone vs Inline

| Aspect | Standalone | Inline |
|--------|-----------|--------|
| Source of truth | `agent.json` + `resources/<Name>/resource.json` | The `.flow`: agent node `inputs` + resource node `inputs` |
| Files you edit | agent.json, resource.json | The `.flow` only |
| Generated files | entry-points.json, bindings_v2.json | The whole `<projectId>/` folder (agent.json, resources/, features/) + bindings |
| Prompt variables | `{{input.<field>}}` | `{{ $vars.<nodeId>.output.<field> }}` |
| Lifecycle | Independent publish | Published with parent flow |
| Best for | Agent runs on its own or is referenced externally | Agent is a step within a flow |

Standalone agents are unaffected by this file — everything in [../../agent-definition.md](../../agent-definition.md) and [../../critical-rules/critical-rules.md](../../critical-rules/critical-rules.md) about editing `agent.json` still applies to them.

## Critical Rules — Inline Agents

1. **Author the agent on the `.flow`, never in `<FlowProjectDir>/<projectId>/`.** That folder is generated by `uip agent refresh --inline-in-flow` — the same projection Studio Web runs on every canvas save. Refresh overwrites `agent.json` and every `resource.json` / `feature.json` from the nodes and deletes entries whose node is gone, so a hand edit there is lost and never reaches Studio Web.
2. **Run refresh after every bulk of `.flow` edits, then validate:**

   ```bash
   uip agent refresh "<FlowProjectDir>/<projectId>" --inline-in-flow --output json
   uip agent validate "<FlowProjectDir>/<projectId>" --inline-in-flow --output json
   ```

   Packaging (`pack`, `debug`, `upload`) reads the generated folder, so a skipped refresh ships the previous agent.
3. **Check that refresh synced from the `.flow`.** The inline refresh result carries `Data.SyncedFromFlow` (the folder files it wrote). **If `SyncedFromFlow` is absent, or `FlowShellified` appears, the installed `uip` predates `.flow`-native inline agents** — an older CLI either packs a stale folder or strips the agent node back to a shell. Stop, upgrade (`npm install -g @uipath/cli@latest`), restore the `.flow` if `FlowShellified` appeared, and re-run refresh.
4. **Refresh once before editing an existing flow.** A flow written by an older Studio Web or older CLI is a *legacy shell* (agent node carries only `source`, `agentInputVariables`, `agentOutputVariables`). Refresh copies the folder's configuration onto the nodes and reports `Data.FlowEmbedded: true`. Re-read the `.flow` afterwards, then edit the nodes.
5. **Reference flow data as `{{ $vars.<nodeId>.output.<field> }}` in the node's prompts.** Never write `{{input.<key>}}`, `contentTokens`, `inputSchema`, or flattened `<nodeId>__output__<field>` keys on the node — refresh and the flow converter derive all of them from the `$vars` tokens.
6. **Add capabilities as resource nodes, never with `uip agent tool add` / `uip agent memory add`.** Those commands write the generated folder; refresh deletes an entry that has no resource node.
7. **Start every resource node's `inputs` from its registry definition's `inputDefaults`**, then set the fields in § Resource Node Inputs. When a node's inputs fail the agent storage schema, refresh fails with `AgentRefreshFlowSyncFailed` and names the node and field — fix the node, never the folder.

## Creating an Inline Agent

```bash
uip agent init "<FlowProjectDir>" --inline-in-flow --output json
```

Returns `Data.ProjectId` — a UUID that becomes the agent node's `inputs.source` and the generated folder's name. The folder it creates holds a placeholder `agent.json`; do not edit it. Then hand the node authoring to the `uipath-maestro-flow` skill (§ Flow Wiring) with the configuration below.

## Agent Node Inputs

The agent node (`uipath.agent.autonomous`) carries every field of the agent. Refresh projects each into the generated `agent.json`:

| Node input | Generated `agent.json` field | Rule |
| --- | --- | --- |
| `source` | `projectId`, `id`, folder name | `ProjectId` from `uip agent init`. Never change it. |
| node `display.label` | `name` | The agent's name. |
| `systemPrompt` | `messages[role=system].content` + `contentTokens` | **Required, non-empty.** Structure: [../../prompting/autonomous-agent-prompting-guide.md](../../prompting/autonomous-agent-prompting-guide.md). |
| `userPrompt` | `messages[role=user].content` + `contentTokens` | **Required, non-empty.** Per-run task + flow data. |
| `model` | `settings.model` | **Required.** `uip agent model list --output json` → [../../model-selection-guide.md](../../model-selection-guide.md). Never `gpt-4o-2024-11-20`. |
| `mode` | `settings.mode` | `standard` (default) or `advanced`. |
| `temperature` | `settings.temperature` | `0` for extraction / classification / judgment. |
| `maxTokenPerResponse` | `settings.maxTokens` | ≤ the model's cap. |
| `maxIterations` | `settings.maxIterations` | Keep `25` with any tool or context. |
| `guardrails` | `guardrails` | Same guardrail objects as a standalone agent — [../guardrails/guardrails.md](../guardrails/guardrails.md). Tool-scoped guardrails (`selector.scopes: ["Tool"]`, `matchNames`) are copied into each matching tool's `resource.json`. |
| `agentOutputVariables` | `outputSchema` | One entry per output field (§ Outputs). |
| `agentInputVariables` | `inputSchema` | **Leave `[]`** — derived from the `$vars` tokens (§ Inputs). |

Example:

```json
{
  "id": "autonomousAgent1",
  "type": "uipath.agent.autonomous",
  "typeVersion": "<DEFINITION_VERSION>",
  "display": { "label": "Billing Resolution Agent" },
  "inputs": {
    "source": "5029c8a8-799b-426a-803f-c4ec75255439",
    "model": "<MODEL_ID>",
    "mode": "standard",
    "systemPrompt": "You resolve billing disputes. ...",
    "userPrompt": "Write a billing resolution email for this dispute:\n{{ $vars.start.output.disputeSummary }}",
    "temperature": 0,
    "maxTokenPerResponse": 16384,
    "maxIterations": 25,
    "guardrails": [],
    "agentInputVariables": [],
    "agentOutputVariables": [
      { "id": "emailSubject", "type": "string", "required": true },
      { "id": "emailBody", "type": "string", "required": true }
    ]
  }
}
```

### Inputs

`{{ $vars.<nodeId>.output.<field> }}` in `systemPrompt`, `userPrompt`, or a resource node's value is the whole input wiring. Refresh flattens each token to an agent input `<nodeId>__output__<field>` in the generated `inputSchema` (typed from the source variable), rewrites the prompt to `{{input.<nodeId>__output__<field>}}`, and the converter emits the matching `JobArguments`. Inputs no token references are pruned.

- The referenced variable must be declared in the flow (trigger fields as `variables.globals[]` entries with `direction: "in"` and `triggerNodeId`) — owned by the `uipath-maestro-flow` skill ([inline-agent guide § Wiring Flow Data](../../../../../uipath-maestro-flow/references/author/plugins/inline-agent/impl.md#wiring-flow-data-into-the-agent)).
- Declare the source variable's real type. A list declared `object` faults `AGENT_STARTUP.INPUT_VALIDATION_ERROR` before the model runs, while both validators pass.

### Outputs

Each `agentOutputVariables[]` entry — `{ "id", "type", "description"?, "required"?, "schema"? }` — becomes one `outputSchema` property and surfaces flat at `$vars.<nodeId>.output.<id>`. Use `schema` for `object` / `array` fields (`{ "type": "array", "items": {...} }`). Declare a typed output per field rather than one `content` string so downstream nodes can consume the result.

## Resource Node Inputs

Each capability is a resource node wired to one of the agent's artifact ports (`tool`, `context`, `escalation`, `memory`). Its `inputs` = the registry definition's `inputDefaults` + `source` (a fresh UUID, the generated `resources/<source>/` folder name) + the fields below. Discovery (which process, index, app, memory space) is unchanged from standalone agents — run it from the linked capability doc, then write the values onto the node instead of into a `resource.json`.

Value-source fields (tool arguments, `query`, built-in inputs) take one shape per mode:

| Mode | Shape |
| --- | --- |
| LLM decides | `{ "mode": "prompt", "textValue": "", "promptValue": "<hint>", "argumentPath": "" }` |
| Flow data | `{ "mode": "variable", "textValue": "", "promptValue": "", "argumentPath": "$vars.<nodeId>.output.<field>" }` |
| Fixed | `{ "mode": "text-builder", "textValue": "<literal>", "promptValue": "", "argumentPath": "" }` |

| Capability | Node type prefix | Discovery | Node inputs (beyond `inputDefaults` + `source`) |
| --- | --- | --- | --- |
| Process / agent / API / Process Orchestration tool | `uipath.agent.resource.tool.{process,agent,api,processorchestration}.<release-key>` | [../process/process.md](../process/process.md) § Discovery | `name`, `description`, `referenceKey` = `Key`, `folderPath` + `properties: { "processName", "folderPath" }` = literal `Name` / `Folder`; one value source per argument (keys seeded by `inputDefaults`); `inputSchema` / `outputSchema` from `uip solution resources get` when the seed is empty. |
| Integration Service connector tool | `uipath.agent.resource.tool.connector.*` | [../integration-service/integration-service.md](../integration-service/integration-service.md) | `inputs.detail`, as the `uipath-maestro-flow` connector plugin's `node configure` writes it. Refresh generates this tool's `resource.json` from `detail` + IS metadata (`Data.ConnectorToolsGenerated`). |
| Built-in tool | `uipath.agent.resource.tool.builtin.<tool>` | [../built-in-tools/built-in-tools.md](../built-in-tools/built-in-tools.md) | `description`; the tool's value-source fields (`query`, `itemsDescription`, `analysisTaskDescription`). Summarize / BatchTransform put the file binding in `source` (`{{ $vars.… }}`). |
| MCP server | `uipath.agent.resource.tool.mcp.*` | [../mcp/mcp.md](../mcp/mcp.md) | `name`, `description`, `slug`, `folderPath`, `referenceKey`, `discoveryMode`, `selectedTools`. |
| Context index | `uipath.agent.resource.context.index.*` | [../context/index.md](../context/index.md) § Discovery | `name`, `description`, `retrievalMode`, `query` value source, `resultCount`, `threshold` (`indexId`, `indexName`, `folderPath` seeded). |
| Escalation | `uipath.agent.resource.escalation[.<variant>]` | [../escalation/escalation.md](../escalation/escalation.md) § Discovery | `name`, `description`, `app: { appName, resourceKey, folderName, appVersion, inputSchema, outputSchema }`, `recipients`, `outcomeMapping`, `_additionalProps: { taskTitle, priority, labels }`. |
| Memory space | `uipath.agent.resource.memory.*` | [../memory/memory.md](../memory/memory.md) | `folderPath` (literal), `name`, `description`, `dynamicFewShotLearning`, `semanticSimilarity`, `kValue`, `searchMode`, `fieldSettings` (`[{ "id", "name", "weight" }]` over agent input names; empty → every input at weight 1). |

Full node JSON, edges, and `definitions[]` / `bindings[]` handling: the `uipath-maestro-flow` skill's [inline-agent guide § Adding Resource Nodes](../../../../../uipath-maestro-flow/references/author/plugins/inline-agent/impl.md#adding-resource-nodes).

## Refresh and Validate

```bash
uip agent refresh "<FlowProjectDir>/<projectId>" --inline-in-flow \
  --bindings-target "<FlowProjectDir>/bindings_v2.json" --output json
uip agent validate "<FlowProjectDir>/<projectId>" --inline-in-flow --output json
```

Refresh, in order:

1. Makes a legacy shell `.flow` self-contained from the folder (`FlowEmbedded: true`) — once per legacy flow.
2. Regenerates `<projectId>/` from the `.flow`: `agent.json` (prompts rewritten to `{{input.…}}` with `contentTokens`, derived `inputSchema`), `resources/<id>/resource.json`, `features/<id>/feature.json`; deletes entries whose node is gone (`SyncedFromFlow`).
3. Generates IS connector tool `resource.json` files from their nodes' `detail`.
4. Applies storage migrations, writes `bindings_v2.json`, and with `--bindings-target` merges the agent's bindings (process, connection, index, memorySpace, app) into the flow project's `bindings_v2.json` — required for `uip solution resources refresh` to create the solution-level resource files. Never hand-edit `bindings_v2.json`.

`validate` is read-only. With `--inline-in-flow` it also fails with `AgentValidationDrift` when the folder no longer matches the `.flow` (a `.flow` edit after the last refresh, or a hand edit in the folder) — fix by re-running refresh.

**Verify end-to-end at `flow debug`**, owned by the `uipath-maestro-flow` skill ([inline-agent guide § Debug](../../../../../uipath-maestro-flow/references/author/plugins/inline-agent/impl.md#debug)): the agent must resolve its inputs rather than echo a literal token.

## Flow Wiring

Per Critical Rule 15 this skill does not invoke flow operations. Tell the user:

> The inline agent's `ProjectId` is `<uuid>`. To wire it into the flow, use the `uipath-maestro-flow` skill — it adds a `uipath.agent.autonomous` node with `inputs.source = <uuid>` and the configuration above, the resource nodes, and their edges. **After all `.flow` edits**, run `uip agent refresh --inline-in-flow` (with `--bindings-target <FlowProjectDir>/bindings_v2.json` when the agent has external capabilities), then `uip agent validate --inline-in-flow`.

## Walkthrough — End-to-End

```bash
# 1. Ensure solution and flow project exist (uipath-maestro-flow skill)

# 2. Get a ProjectId for the agent
uip agent init "<FlowProjectDir>" --inline-in-flow --output json

# 3. Discover each capability (process / index / app / memory) per its capability doc

# 4. Hand off to uipath-maestro-flow: agent node (inputs per § Agent Node Inputs),
#    resource nodes (inputs per § Resource Node Inputs), edges, variables.

# 5. Regenerate the agent folder from the .flow and propagate bindings
uip agent refresh "<FlowProjectDir>/<projectId>" --inline-in-flow \
  --bindings-target "<FlowProjectDir>/bindings_v2.json" --output json

# 6. Validate the agent folder against the .flow (read-only)
uip agent validate "<FlowProjectDir>/<projectId>" --inline-in-flow --output json

# 7. Refresh solution resources and upload
uip solution resources refresh --output json
```

Every later change repeats 4 → 7: edit the nodes, refresh, validate.

## What Happens at Pack Time

`uip solution pack` / `uip solution upload` / `uip maestro flow pack` build each inline agent from its generated folder:

1. Reads `<FlowProjectDir>/<inputs.source>/` (agent.json, resources/, features/)
2. Builds the agent definition and its bindings
3. Converts the `.flow` to BPMN — the agent node's `JobArguments` come from the `$vars` tokens
4. Writes into the package:

```
content/
├── process.bpmn
├── operate.json            # contentType: "Flow"
├── entry-points.json       # type: "processorchestration"
├── bindings_v2.json
└── <agentProjectId>/
    ├── agent.json          # Built AgentDefinition
    └── .agent-builder/
        ├── agent.json      # Execution model
        └── bindings.json
```

Studio Web reads the `.flow` itself: a self-contained agent node is authoritative on import, and Studio Web regenerates the same folder on its next save.

## BPMN Execution Engine Notes

- **Inline agents**: `ServiceTask` with `serviceType: "Orchestrator.StartInlineAgentJob"`, executed from the packaged `content/<agentProjectId>/agent.json`.

The execution is asynchronous. The flow pauses at the agent node and resumes when the agent job completes.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `AgentRefreshFlowSyncFailed` | A node's inputs fail the agent storage schema, or a resource node has no `definitions[]` entry — `Data.Errors` names it | Fix that node (re-seed from `inputDefaults`, set § Resource Node Inputs); re-run refresh |
| `AgentValidationDrift` — `out of sync with the .flow` | `.flow` edited after the last refresh, or the folder was hand-edited | Run refresh |
| Refresh result lacks `SyncedFromFlow`, or shows `FlowShellified` | CLI too old | Critical Rule 3 |
| `flow validate`: `System prompt is required` | Node `systemPrompt` missing or `""` | Write a real prompt on the node |
| Agent echoes a literal `{{input.X}}` / `$vars…` | Runtime token form written on the node, or undeclared variable | `{{ $vars.<nodeId>.output.<field> }}` + declared variable; refresh |
| Studio Web debug: "Could not find process for tool" | Bindings not propagated to the flow project | Refresh with `--bindings-target`, then `uip solution resources refresh` |
