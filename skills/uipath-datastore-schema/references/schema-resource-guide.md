## The resource file

`resources/solution_folder/schema/<Name>.json`, created by:

```bash
uip solution resources add --source local --kind Schema --name <Name> --output json
```

```json
{
  "docVersion": "1.0.0",
  "resource": {
    "name": "SalesSchema",
    "kind": "schema",
    "apiVersion": "dataservice.uipath.com/v2",
    "isOverridable": false,
    "dependencies": [],
    "runtimeDependencies": [],
    "folders": [ { "fullyQualifiedName": "solution_folder" } ],
    "spec": {
      "name": "SalesSchema",
      "scope": "Folder",
      "description": "",
      "changesets": [ ]
    },
    "locks": [],
    "key": "35760409-c3d6-436a-8b87-72f73c7a207d",
    "files": []
  }
}
```

| Field | Rule |
|---|---|
| `resource.isOverridable` | `false`: the changesets ship as written and cannot be overridden per deployment. `resources add` omits it; add it. |
| `resource.key` | The resource's identity across every deploy and upgrade. Generated by `resources add`; never change it. |
| `spec.name` | Starts with a letter; 3–100 letters or digits. Shown in error messages. May be renamed in a later version. |
| `spec.scope` | `Folder` (default) or `Tenant`, any case. Fixed after the first install. |
| `spec.description` | Optional. |
| `spec.changesets` | Required, at least one changeset. `resources add` writes `""`: replace it with an array. Rules: [changes-reference.md](changes-reference.md). |

A solution may hold several Schema resources. Each is its own schema: its changesets can only touch its own tables, and two resources cannot create the same table in the same folder (or both tenant-wide).

Schema resources need the `solution-entity-sql` feature on the tenant; otherwise the deploy fails with `Schemas are not enabled for this tenant`.

## Scope

| | `Folder` | `Tenant` |
|---|---|---|
| Tables | One copy per folder the solution deploys to | One set for the whole tenant |
| Two deployments of the solution | Each has its own tables | The second joins the first's schema and runs only what it lacks |
| Querying | The request names the folder (`X-UiPath-FolderKey` / `X-UiPath-FolderPath`) | The request names no folder |
| Permissions to query | The caller's folder record permissions | The caller's tenant data permissions |
| Table names unique | Within the folder | Within the tenant |

Pick `Folder` for data that belongs to one deployment (a department's own copy); pick `Tenant` for data every deployment shares (reference data, a shared queue of work).

## What a deploy does

For each Schema resource, in one transaction with the rest of the deploy:

1. Finds the installed schema by resource key (this deployment's, or for tenant scope, the tenant's).
2. Takes the changesets not installed yet, in ascending number.
3. For each: evaluates its preconditions, then runs its changes as SQL Server statements, then records it as installed (with a checksum and the SQL that ran).
4. Any failure rolls back the whole deploy: nothing is half-applied.

Tables are created in the tenant's data database as `dbo.<Table>_<id>`; apps never see that name, they use the logical name. Constraints are named by install (`PK_…`, `DF_…`, `UQ_…`, `FK_<name>_…`).

- **Rollback and downgrade**: a package whose highest changeset is below what is installed, or a rollback deploy, changes no tables.
- **Uninstall**: leaves the tables and their data in place.

## Evolving a schema

| Want to | Do |
|---|---|
| Add a table, column, index, key, or rows | New changeset with the next number |
| Fix a mistake in an installed changeset | New changeset that corrects it; leave the old one unchanged |
| Rename a column or table | Not supported, and `update` cannot copy one column into another (values are literals only). Choose names carefully; to move data, add the new column or table and have the app copy it through QueryExecutor |
| Remove a table | Not supported (no `dropTable`). Stop using it; it stays in place |
| Change a column's type | `modifyDataType` in a new changeset; drop and recreate indexes on it, and foreign keys that use it |
| Make a column required | Not supported directly (no `addNotNullConstraint`): add a new `nullable: false` column with a default |
| Seed rows once | `insert` in a changeset with a `MARK_RAN` precondition that checks the table is empty |

Editing an installed changeset changes nothing on tenants that installed it, while new tenants run the edited version: the two drift apart. Treat installed changesets as frozen.

## Deploy errors

Messages name the Schema (`'SalesSchema'`) and the path in the file (`changesets[1].changes[0].addColumn.columns[0].column`).

| Message contains | Cause and fix |
|---|---|
| `has unknown property` | A misspelt or unsupported property (`id`, `author`, `name` on a changeset, `autoIncrement`, `schemaName`). Remove it. |
| `changeset must be a whole number from 1 to 999999999` | `"changeset": "1"` or `1.0`. Use a JSON integer. |
| `is not a supported change` | `sql`, `dropTable`, `renameColumn`, … See the supported list. |
| `must be an object with the single property 'column'` | A column without its `{ "column": … }` wrapper. |
| `is not a supported column type` | See [column types](changes-reference.md#column-types). |
| `cannot be kept exactly in SQL Server. Write it as a string` | A decimal JSON number: write `"12.5"`. |
| `a column added with nullable false needs a default value` | Give the new `NOT NULL` column a default. |
| `is numbered below changeset {n}, which is already installed` | Renumber the new changeset above `{n}`. |
| `uses table '{t}', which its schema does not have` | The table is another resource's, not created yet, or misspelt. |
| `creates table '{t}', which another schema already has in this folder/tenant` | Another Schema resource owns that name there, or this resource's key changed (deleted and re-added). Rename the table, or restore the original key. |
| `creates table '{t}', which its schema already has` | A `createTable` for a table an earlier changeset created. |
| `drops column … which a foreign key uses` / `changes the type of column … which a foreign key uses` | Drop the foreign key first, in the same changeset ([example](changes-reference.md#foreign-keys)). |
| `stopped: its sqlCheck returned '{a}', not '{e}'` | A `HALT` precondition did not hold. Use `MARK_RAN` to skip instead, or fix the check. |
| `was installed folder-scoped; a later version cannot make it tenant-scoped` | Scope changed. Put it back. |
| `cannot create the same table` | Two Schema resources in the package create the same table in one place. |
| `failed at statement {k}: …` | SQL Server refused a statement: an unknown column in `where`, an index on a `(MAX)` column, a retype an index blocks. Read SQL Server's text after the colon. |
| `Schemas are not enabled for this tenant` | The tenant lacks the feature; ask an administrator. |
