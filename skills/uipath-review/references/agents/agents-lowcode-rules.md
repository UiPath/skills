# Agents — Low-code Judgment Rule Catalog

Judgment rules for **low-code** agents (`agent.json`). Each rule requires reading source and reasoning; regex/count/schema-walk checks are insufficient. Use the row schema in [`../rule-format.md`](../rule-format.md).

> **Judgment-only catalog.** Run `uip agent review "<PROJECT_DIR>" --output json` **first** (SKILL.md Step 2.5). It returns deterministic low-code findings—structural gates, schema-property presence, placeholder cross-refs, eval-set structure and schema cross-refs, and guardrail configuration validity—in the same rule format. Then apply these rules.

Read [`../rule-format.md`](../rule-format.md) and [`../rule-catalog-workflow.md`](../rule-catalog-workflow.md) first.

## Layouts

Detect the layout before reading each rule's sources.

| Layout | Identifier | Key files |
|---|---|---|
| **Normalized** | One JSON file with snake_case top-level keys (`system_prompt`, `tools`, `datasets`, `input_schema`, `output_schema`, `user_prompt`) | The single JSON file |
| **Agent-builder** | Root `agent.json` with camelCase keys, sibling `project.uiproj`, and `resources/<Name>/resource.json` | `agent.json`, `resources/*/resource.json`, `evals/eval-sets/*.json`, `evals/evaluators/*.json` |

Rules tagged `(agent-builder only)` skip silently on normalized layout; `(normalized only)` skip on agent-builder. Untagged rules apply to both with layout-aware `detection_method`.

## How to apply rules

Sections group checker classes: `EvalsChecker`, `SchemaChecker`, `ToolsChecker`, `GuardrailsChecker`, and `GeneralChecker`. Every `detection_method` is a judgment instruction: read the named source, reason, emit only when criteria hold, and record the reasoning in the finding's `description`.

## EvalsChecker

| rule_id | severity | category | trigger | detection_method | suggested_fix |
|---|---|---|---|---|---|
| `LC_EVAL_INPUT_DIVERSITY` | warning | evals | Eval datapoints omit production scenario classes | Read `evals/eval-sets/*.json`, agent purpose, `inputSchema`, tools, and escalations. Semantically assess coverage of happy path, edge/boundary values, malformed or missing input, ambiguous/unresolvable requests, every declared side effect (each tool), and every escalation path. Emit when a whole class is absent or datapoints are paraphrases; name missing classes and do not assert a target count. file = eval set JSON. | Add datapoints for missing classes, each declared tool, and each escalation path. |
| `LC_EVAL_GROUND_TRUTH_SWAPPED` | warning | evals | Near-identical inputs have different `expectedOutput` values | Read `evals/eval-sets/*.json`; compare datapoint pairs for substantially overlapping `inputs` content, such as `email_subject` + `email_body` substring overlap > 80%. Emit one finding per likely swapped pair—the opposite pattern from deterministic duplicate-output checking—element = `<id_1>,<id_2>`. file = eval set JSON. | Inspect both datapoints; correct the label or split the scenarios clearly. |
| `LC_EVAL_JUDGE_FOR_CLOSED_CLASS` | warning | evals | An LLM judge evaluates a closed-class output field | Read eval `evaluatorRefs` and `outputSchema.properties`. If any output property has `.enum` and a referenced evaluator is an LLM judge (`evaluatorTypeId: "uipath-llm-judge-output-semantic-similarity"` or similar), emit one finding per `(eval-set, judge-evaluator)` pair. `uipath-multiclass-classification` / `uipath-exact-match` provides the relevant signal without judge variance. file = eval set JSON. | Replace the judge with `uipath-multiclass-classification` or `uipath-exact-match`. |
| `LC_EVAL_ARCHETYPE_FIT` | warning | evals | Evaluators do not measure the agent's contract or main failure risks | Read purpose, tools, output schema, scenarios, and evaluator configurations. Assess whether evaluators cover exact/multiclass comparison for closed outputs, structural comparison for structured integration results, trajectory/tool behavior when path or side effects matter, and rubric judgment for genuinely subjective generation. Emit the most specific mismatch; skip a closed-class mismatch already covered by `LC_EVAL_JUDGE_FOR_CLOSED_CLASS`. file = eval set JSON. | Replace or supplement evaluators for the primary contract, decision path, and highest-risk failures. |
| `LC_EVAL_JUDGE_RUBRIC_FIT` | warning | evals | LLM-judge instructions are vague or mismatched | Read each LLM-judge prompt, criteria, score/label contract, and target output. Emit when subjective assessment lacks explicit criteria, evidence expectations, score-level distinctions, or a matching rubric. Do not require hidden chain-of-thought or a particular model. file = evaluator JSON, element = evaluator name. | Define observable criteria, score/label boundaries, and a concise evidence-based justification for audit. |
| `LC_EVAL_MOCK_CONTRACT_DRIFT` | warning | evals | A mock response contradicts the mocked tool's output contract | Read mocks in `evals/eval-sets/*.json` and each mocked tool's `outputSchema` (normalized: `.tools[]`; agent-builder: `resources/<Name>/resource.json`). Compare property names, types, required fields, and enum members. Emit per mismatching mock; skip tools without declared output schemas. file = eval set JSON, element = `<tool_name>`. | Align the mock with the declared schema, or correct the schema if the mock is authoritative. |
| `LC_EVAL_AGENT_DEFINITION_DRIFT` | warning | evals | An eval expects an unavailable resource, tool, or behavior | Read each datapoint's expected behavior, expected output, and simulation instructions against the definition, tools, and resources. Emit per datapoint when it names an index, resource, tool, escalation, or behavior the configured agent cannot provide. A paraphrase of a bound resource is not drift; a name bound nowhere is. file = eval set JSON, element = datapoint id. | Point the expectation at a declared element or bind the missing element. |

## SchemaChecker

| rule_id | severity | category | trigger | detection_method | suggested_fix |
|---|---|---|---|---|---|
| `SCHEMA_NO_DESCRIPTIONS` | judgment | schema | Input/output properties lack informative descriptions | Read `.input_schema` / `.output_schema` in normalized JSON or `agent.json.inputSchema` / `outputSchema` in Agent Builder. Judge useful semantic guidance, not mere presence; assess input and output separately. | Add a useful description to every property. |
| `LC_OUTPUT_FORMAT_PROMPT_DRIFT` | warning | schema | System prompt output instructions conflict with `outputSchema` | Read system prompt and `outputSchema`; compare instructed shape—such as `respond with a single sentence` or `answer in markdown`—with structured JSON or flat-string schema. file = system prompt source. | Align prompt and schema, choosing one source of truth. |
| `LC_INPUT_SCHEMA_OVERLAP` | warning | schema | At least two input fields could hold the same content | Read `inputSchema.properties`; assess overlapping names/descriptions such as `query`, `question`, `text`, `prompt`, and `input`. Emit when the LLM must disambiguate at runtime. file = schema source, element = `<field_a>,<field_b>`. | Merge fields or differentiate names and descriptions. |
| `LC_OUTPUT_ENUM_VS_PROMPT_DRIFT` | warning | schema | Output enum disagrees with the prompt's category list | Read `outputSchema.properties.<X>.enum` and prompt classification lists such as `Classify into: A, B, C`. Emit if either side has extras: runtime rejects prompt-only classes, while schema-only classes are not prompted. file = schema or prompt source. | Reconcile the prompt list and `outputSchema.enum`. |
| `LC_OUTPUT_CLASSIFIER_NO_ENUM` | warning | schema | Classifier-shaped primary output has no `enum` | Read `outputSchema`. Treat it as classifier-shaped when it has one primary string field named like `class`, `classification`, `label`, `category`, `intent`, or `decision`, or when the prompt enumerates fewer than 10 categories. Emit if that field lacks `enum`. file = schema source, element = field name. | Add `"enum": [...]` to the field. |
| `LC_OUTPUT_DECISION_NO_RATIONALE` | info | schema | Consequential decision output records no rationale | Read `outputSchema` and purpose. Emit only for consequential classification, approval, routing, or eligibility decisions whose properties are terminal values—enum, boolean, identifier, or score—with no rationale, evidence, or citation. Do not flag passthrough or formatting agents. file = schema source. | Add a `reasoning` / `justification` / `citations` property and prompt for it. |
| `LC_OUTPUT_CONSUMER_DRIFT` | warning | schema | An in-scope consumer reads undeclared fields, types, or states | Apply only when Step 1 lists a consumer such as a sibling flow, RPA project, API workflow, or invoking agent. Read consumer use and `outputSchema`; emit per concrete omitted property, type mismatch, or impossible status/failure branch. With no in-scope consumer, the subject set is empty; an out-of-scope caller is not evidence, and an empty subject set is not a skipped rule. file = consumer source, element = `<property>`. | Add the property/state to `outputSchema` or read what the agent declares. |

## ToolsChecker

| rule_id | severity | category | trigger | detection_method | suggested_fix |
|---|---|---|---|---|---|
| `VAGUE_TOOL_DESCRIPTION` | judgment | tools | Tool description is missing or insufficient for selection | Walk normalized `.tools[]` or agent-builder `resources/*/resource.json` where `.type == "tool"`. Read `.description`; require purpose, side effects, and when to use versus siblings. Blank or boilerplate such as `Process invoice` fires; a 2-3 sentence description covering those points does not. file = tool source, element = tool name. | Write a 2-3 sentence description covering purpose, effects, and use/non-use conditions. |
| `LC_TOOL_MINIMALITY_SUFFICIENCY` | warning | tools | Tools are unnamed by the prompt, or prompt responsibilities lack tools | Read tool list and system prompt. Check both directions: every tool maps to a stated responsibility, and every stated responsibility has a tool. Emit one finding per gap and name it. file = system prompt source. | Add the responsibility, add a tool, or remove the unused tool. |
| `LC_TOOL_OVERLAP` | warning | tools | Tools have substantially overlapping descriptions or input schemas | Read all descriptions and `inputSchema`s pairwise. Emit when users could plausibly apply two tools to the same request or schemas are interchangeable. element = `<tool_a>,<tool_b>`. file = tool source. | Sharpen selection cues or merge redundant tools. |
| `LC_TOOL_DANGEROUS_COMBINATION` | warning | tools | Tool combinations create a capability or risk absent from individual tools | Read the full list pairwise/N-wise. Flag combinations such as read/search/retrieve plus write/send/create/API with no output guardrail, creating a data-exfiltration path. file = tool source, element = `<tool_a>,<tool_b>`. | Add a guardrail such as `pii_detection` or scope restriction, or remove one tool. |
| `LC_TOOL_DELEGATION_DEPTH` | warning | tools | An agent tool lacks delegation criteria | Identify resources with `.type == "agent"`; read the system prompt and emit when it does not say when to delegate versus handle directly. file = tool source, element = tool name. | Add delegation criteria. |
| `LC_TOOL_DESCRIPTION_MISLEADING` | info | tools | Description contradicts declared input/output schemas | Read each description, `inputSchema`, and `outputSchema`. Emit per clear semantic mismatch in return type, fields, or argument count. file = tool source, element = tool name. | Reconcile description and schemas. |
| `LC_TOOL_PURPOSE_AUTHORITY_FIT` | warning | tools | Tool authority exceeds the business purpose | Read prompt, business context, and tools. Emit when a read-only/advisory use case has unnecessary create, update, delete, send, admin, or cross-system capability, even if mentioned by the prompt. file = tool source, element = tool name. | Remove, narrow, or constrain the tool to required action and scope. |
| `LC_PROMPT_REFERENCES_NONEXISTENT_RESOURCE` | warning | tools | Prompt relies on an unconfigured executable or grounded resource | Read prompt and configured names/descriptions; match semantically, distinguishing business nouns from executable or grounded resources. Emit only when no plausible configured match exists; name the unsupported instruction. file = system prompt source. | Configure it, name the actual resource, or remove the instruction. |
| `LC_MULTI_TOOL_NO_SEQUENCING` | warning | tools | Implicitly ordered tools have no prompt order | Identify canonical pairs such as `search*` + `summarize*`, `get*` + `create*`, and `validate` + `submit`. Read prompt; emit when no `first`, `then`, `after`, or numbered ordering appears. file = system prompt source. | Add ordered steps or sequencing language. |
| `LC_UNGROUNDED_DOMAIN_KNOWLEDGE` | warning | tools | Prompt depends on organization-specific knowledge unavailable to the agent | Read prompt for internal policy, catalog, thresholds, ownership, or other non-general facts; read context resources and tools. Emit when nothing supplies the knowledge. Do not flag facts stated inline. `LC_TOOL_RESPONSE_NOT_GROUNDED` covers retrieval that exists without grounding; this rule covers absent retrieval. file = system prompt source. | Configure context/retrieval or state the facts inline. |
| `LC_CONTEXT_SOURCE_OVERLAP` | warning | tools | Context sources provide no retrieval-selection cue | Read every `$resourceType: "context"` resource's `description`, `query.description`, and referenced index. Emit per pair when descriptions do not distinguish corpus and question types. Single-source agents have an empty subject set. `LOWCODE_CONTEXT_NO_DESCRIPTION` owns presence; this rule judges distinctness. file = context resource, element = `<source_a>,<source_b>`. | Describe each corpus and question types clearly. |
| `LC_CONTEXT_RETRIEVAL_SETTINGS_FIT` | judgment | tools | `threshold` / `resultCount` do not fit corpus and answer contract | Read settings, corpus, prompt contract, and representative positive, ambiguous, and no-answer queries. `threshold: 0` accepts every match regardless of score; higher thresholds improve precision but can drop relevant passages. Assess recall, latency, token cost, whether no-answer queries can still return a full `resultCount`, and whether the prompt can say no answer. Name the failing query class; assert no target number. file = context resource, element = resource name. | Tune `threshold` / `resultCount` with representative queries and add a no-answer eval datapoint. |
| `LC_TOOL_RESPONSE_NOT_GROUNDED` | warning | tools | RAG-shaped retrieval has no grounding instruction | First confirm RAG shape: unstructured prose intended for citation, or Context Grounding index resource (`$resourceType: "context"` with `contextType: "index"`). Structured-record tools such as `searchOrders` and `lookupCustomer` do not trigger. Read system prompt and every context resource's `description` / `query.description`; emit when no instruction says to answer only from retrieval, cite sources, or say `I don't know` when none is found. file = system prompt or context resource. | Add grounding guidance to the system prompt or context description. |

## GuardrailsChecker

> **Validator name authority.** Use only names supported by the target layout.
>
> **SDK-documented built-ins** (confirmed by `uipath-python` SDK docs):
>
> | Validator | When it's needed | Valid scope | Valid stage |
> |---|---|---|---|
> | `pii_detection` | Agent handles personal data (names, emails, addresses, health info) | Agent, Llm, Tool | Pre or Post |
> | `prompt_injection` | Agent accepts free-text user input | Llm only | PreExecution only |
>
> **Agent Builder platform-documented** (not in `uipath-python` public SDK docs):
>
> | Validator | When it's needed | Valid scope | Valid stage |
> |---|---|---|---|
> | `harmful_content` | Agent generates open-ended content | Agent, Llm, Tool | Pre or Post |
> | `intellectual_property` | Agent generates code or text | Agent, Llm only | PostExecution only |
> | `user_prompt_attacks` | User-facing agent, jailbreak risk | Llm only | PreExecution only |
>
> When recommending the three platform-documented types, do not cite them by name unless already present in the project's `guardrails` array or agent-builder schema. Say: *Add an appropriate content-safety guardrail supported by this agent layout.* This applies to `LC_GUARDRAIL_RECOMMENDED`.
>
> **Apply these through the structured workflow.** Run [`guardrails/guardrails-review.md`](guardrails/guardrails-review.md) Step 0: fetch the live `uip agent guardrails catalog` + `list` with a 30-min cache. Then run **Audit Mode** for existing guardrails and **Recommend Mode** for missing ones, using the same live catalog and modeling `uipath-agents` recommend capability. The review CLI (Step 2.5a) owns all FORMAT/SCHEMA/SET-MEMBERSHIP checks (`GUARDRAIL_*` / `GUARDRAIL_CUSTOM_*` / `LOWCODE_*GUARDRAIL*`); these rules apply only to format-valid guardrails and never re-flag a CLI format finding. If the catalog is unavailable, defer Audit-Mode rows (Rules Skipped) as specified in Step 0.

| rule_id | severity | category | trigger | detection_method | suggested_fix |
|---|---|---|---|---|---|
| `LC_GUARDRAIL_RECOMMENDED` | info | guardrails | A matching catalog guardrail is absent | Apply `guardrails/guardrails-review.md` **Recommend Mode**. For each catalog entry whose `when_to_use` / `use_cases` / `security_risk_addressed` matches prompt, schemas, or tools and is absent from `.guardrails[]`, emit one finding. Name guardrail / `security_category`, matched use case, recommended scope and **action**: **block/escalate** when protection is needed (PII that must not enter, injection, harmful content), or **log** for audit-only handling. Include source evidence as `<source path>: <exact matching identifier(s)>`; copy schema properties, tool names, and resource names verbatim, e.g. `agent.json inputSchema.properties: customer_email, full_name, ssn`. De-dup by `security_category`; do not name platform-documented validators unless already present. file = `agent.json` (or normalized JSON). | Add the named guardrail at catalog-recommended scope/action, citing `examples[].config`: block/escalate for protection, log for audit. |
| `LC_GUARDRAIL_ACTION_INEFFECTIVE` | judgment | guardrails | A valid guardrail's action is ineffective or counterproductive | Apply **Audit Mode → Actionability**. For each format-valid guardrail, compare `validator`, `selector.scopes`, and `$actionType` with catalog `when_not_to_use` / `examples[].config` for that scope. Flag security-critical `log` where example uses `block`, `pii_detection` `Block`/`Filter` at Tool when the tool needs PII, and `pii_detection` `Log` at Agent/Llm. Name recommended action. file = `agent.json`, element = guardrail name. | Use the catalog action or move the guardrail to an effective scope. |
| `LC_GUARDRAIL_MISAPPLIED` | judgment | guardrails | A valid guardrail matches its validator's `when_not_to_use` | Apply **Audit Mode → Relevance**. Read catalog `when_not_to_use` / `NOT_recommended_for`; emit when agent context matches a disqualifying condition, such as a generate-only agent with no user input carrying PII guardrails. Cite the matched clause. file = `agent.json`, element = guardrail name. | Remove it or document why the agent differs from the condition. |

## GeneralChecker

Covers prompt quality, settings fit, failure modes, and prompt/schema reasoning.

| rule_id | severity | category | trigger | detection_method | suggested_fix |
|---|---|---|---|---|---|
| `LC_PROMPT_ROLE_DEFINITION` | warning | general | Prompt does not open with a clear role/persona | Read prompt; require the opening paragraph to state what the agent is and does. file = system prompt source. | Add an opening sentence such as `You are an X that does Y.` |
| `LC_PROMPT_WHEN_GUIDANCE` | warning | general | Prompt explains capabilities but not when to use tools | Read prompt and tools; emit per tool lacking a use condition. Capability-only text is insufficient. file = system prompt source, element = tool name. | Add a `use this when …` sentence for each tool. |
| `LC_PROMPT_SCOPE_BOUNDARIES` | warning | general | Prompt does not state what the agent must not do | Require explicit boundaries such as `Do not …`, `Only handle …`, or `If unsure, escalate`. file = system prompt source. | Add a Scope & Boundaries section. |
| `LC_PROMPT_OUTPUT_FORMAT` | warning | general | Structured schema has no prompt instructions for populating fields | If `outputSchema` has named fields rather than only a string, read prompt and emit when it does not explain field population. file = system prompt source. | Add an Output Format section with structure or sample. |
| `LC_PROMPT_INSTRUCTION_CONFLICTS` | warning | general | Prompt contains contradictory instructions | Read the full prompt and emit per contradiction, such as `Always respond in JSON` alongside `Write your response as a friendly paragraph`. file = system prompt source. | Pick one instruction and reconcile/remove the other. |
| `LC_PROMPT_OVERSPECIFICATION` | info | general | Exact-phrase instructions make paraphrases brittle | Emit when prompt handles many trivial paraphrases individually, such as a 3-page prompt with 47 explicit phrases. file = system prompt source. | Describe input categories instead of enumerating phrases. |
| `LC_PROMPT_STRUCTURE` | info | general | Prompt complexity hides responsibilities, tools, boundaries, output, or precedence | Read prompt with tools, schemas, and decision paths. Emit when multiple concerns are undifferentiated or precedence is unclear; do not use fixed character/line thresholds, and do not flag a short single-purpose prompt. file = system prompt source. | Use concise sections, bullets, or ordered steps where they improve precedence and maintenance. |
| `LC_PROMPT_EXAMPLE_MAINTAINABILITY` | info | general | Inline examples encode deployment cases better held in evals/configuration | Compare examples with reusable behavior, eval scenarios, and deployment data. Emit when examples duplicate tests, hard-code volatile facts, or require edits for customer cases. Do not flag stable output-contract examples or balanced ambiguous categories. file = prompt source. | Move volatile cases to eval sets/configuration; retain stable examples. |
| `LC_PROMPT_DEPLOYMENT_SPECIFIC_LOGIC` | warning | general | Prompt hard-codes values expected to vary by deployment | Read prompt with resources, context, schemas, and deployment model. Flag customer/tenant/environment/policy values, identifiers, thresholds, recipients, or rules presented as universal when variable. Do not flag values fixed by declared scope. file = prompt source. | Move variable values to configuration/grounded context. |
| `LC_PROMPT_STOPPING_CRITERIA` | warning | general | Prompt lacks a stop for unresolvable cases | Require a soft stop, such as `If you cannot determine the answer after 3 attempts, respond with what you have`; `maxIterations` alone is insufficient. file = system prompt source. | Add explicit unresolved-case stopping instructions. |
| `LC_PROMPT_ESCALATION_CRITERIA` | warning | general | Uncertainty or high-risk decisions lack usable escalation criteria | Read prompt, schemas, tools, escalations, and business decision. Identify uncertainty, approval, policy-exception, safety, financial, and destructive-action conditions. Emit when an escalation path lacks triggers or the use case clearly needs one but has none. Distinct from stopping after failed attempts. file = system prompt source. | State triggers and handoff information; add an escalation resource when required by the flow. |
| `LC_SETTINGS_MAXITERATIONS_FIT` | judgment | general | `maxIterations` conflicts with purpose | Read `.settings.maxIterations` and prompt. Simple classifiers rarely need >3-5; complex multi-tool research may need 20-30. Flag extreme values inconsistent with purpose and explain. file = `agent.json` or normalized source. | Adjust to actual loop complexity. |
| `LC_SETTINGS_TEMPERATURE_FIT` | judgment | general | `temperature` is unfit for the task | Read `.settings.temperature` and prompt. Temperature 0 fits classification/extraction; non-zero classifiers risk inconsistent labels. Explain mismatch. file = `agent.json` or normalized source. | Use 0 for deterministic tasks; 0.3-0.7 for conversational generation. |
| `LC_SETTINGS_MAXTOKENS_FIT` | judgment | general | `maxTokens` greatly exceeds the contracted response without another bound | Read `.settings.maxTokens`, schema, prompt format, and eval `expectedOutput` sizes. Compare by orders of magnitude with generous overhead; cite observed expected-answer size and do not flag a platform default alone. file = `agent.json` or normalized source. | Lower `maxTokens` or bound length in the prompt. |
| `LC_SETTINGS_MODEL_FIT` | judgment | general | Model is unfit for workload | Read `.settings.model` with purpose, tools, cost, and latency. Assess capability/cost/latency; flag an oversized model for lookup or undersized model for orchestration. Requires a recognizable vendor/platform identifier; do not apply to custom/aliased deployment names whose model is unknowable from the string. file = `agent.json` or normalized source. | Select a workload-appropriate model. |
| `LC_PLACEHOLDER_VALUE` | warning | general | Authored value remains scaffold/default placeholder | Read agent/project `name`, context `description` / `query.description`, index and alias names, eval `expectedOutput` and mocks, and evaluator prompts. Flag unchanged defaults such as `Test`, `A demo … index`, `TODO`, stock scaffold text, `MyAgent`-style stand-ins, or typo'd names. Model aliases (BYOM) are not free to change; do not flag them. file = value's file, element = field path. | Replace placeholders with project content. |
| `LC_FAILURE_HALLUCINATE_ARGS` | warning | general | Required tool fields lack descriptions needed to infer valid values | Walk tools and required fields; emit when fields are not self-explanatory and the LLM must guess values or formats. file = tool source, element = `<tool_name>:<param>`. | Describe valid values and format for every required parameter. |
| `LC_FAILURE_WRONG_TOOL` | warning | general | At least two descriptions could apply to the same request | Read all descriptions from a user's perspective and emit per ambiguous pair. file = tool source, element = `<tool_a>,<tool_b>`. | Sharpen selection criteria. |
| `LC_FAILURE_PROMPT_INJECTION` | warning | general | Untrusted instruction boundaries fail or prompt contains jailbreak fragments | Fire on either shape: (a) user/retrieved/tool content can be interpreted as instructions because no effective data boundary/sanitization exists and no suitable prompt-injection guardrail is active; literal delimiters are not required when another control works; or (b) system prompt overrides platform safety, contains DAN-style markers (`ignore previous`, `no restrictions`, `do anything now`), or says to behave as another assistant (`As ChatGPT, …`). file = source of risk. | Treat untrusted content as data and add sanitization or an appropriate prompt-injection guardrail; rewrite adversarial system instructions. |
| `LC_FAILURE_IRREVERSIBLE_ACTION` | warning | general | Create/delete/modify tools have neither escalation nor confirmation | Walk tools for create/delete/modify capabilities; read escalation resources and prompt. Emit when no escalation path or confirmation requirement exists. file = tool source. | Add escalation gating or require confirmation. |
| `LC_FAILURE_AUTHORITY_ESCALATION` | warning | general | Admin tools lack contextual restrictions | Walk tools for process invocation, queue manipulation, entity modification, and other admin capabilities; read prompt. Emit when unrestricted. file = system prompt source. | Restrict tools to roles/scenarios or add a guardrail. |
| `LC_ESCALATION_OVERBROAD` | warning | general | Escalation uses universal quantifiers without narrowing | Read escalation and channel `description`s. Flag `always escalate`, `every classification`, `all responses`, `any output`, or `regardless of intent` near the start when no condition such as `if confidence < X`, `when classification is Uncertain`, or `only for` narrows it. file = escalation source, element = escalation name. | Add a narrowing condition or document why everything must escalate. |
| `LC_PROMPT_FEW_SHOT_MISSING` | warning | general | Rich structured schema has no concrete prompt output example | If schema has ≥3 fields, or ≥2 with at least one nested, read prompt for `Example: {…}`, an `Output format:` block with values, or another concrete sample. Emit when absent; 1-2 flat fields do not trigger. file = system prompt source. | Add a concrete example output. |
| `LC_PROMPT_NEGATIVE_HEAVY` | warning | general | More than 50% of distinct instructions are negative | Tokenize sentences/bullets as instructions and count `do not`, `never`, `avoid`, `must not`, and `don't`; emit when >50%. file = system prompt source. | Rewrite negatives positively where possible. |
| `LC_USER_PROMPT_BIASED_EXAMPLE` | warning | general | User message ends with an unconditional concrete classification example | All must hold: user text has `Example of correct output:`, `Example output:`, `For example:`, `Sample output:`, or similar; example body is JSON-shaped with concrete classification values such as `classification: Accepted` or `intent: approve`; and it is not conditioned on input such as `for an acceptance email` or `if the user is asking about billing`. file = user message source. | Remove it, move it to the system prompt as one of several balanced examples, or condition it on input shape. |

## What this catalog cannot do

The agent applies rules to checked-in project source. It cannot:

- Verify runtime LLM compliance; run the agent to confirm it.
- Verify runtime tool selection; overlapping descriptions are risk indicators only.
- Verify guardrails fire correctly; structural configuration is not service behavior.
- Validate live IDs such as connection IDs, index names, or recipient addresses; these require API calls.
