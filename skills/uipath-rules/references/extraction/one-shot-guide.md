# Quick Draft (IXP) Guide

Use only when the user picked `Quick draft (IXP)` in Framing ([start-guide.md](start-guide.md)). It replaces Intake through Extraction, handles one document only, and always falls back to the guided path when it cannot run. Never retry a run that has started: the API takes no idempotency key and each run is billed. IXP's DMN is a draft with box citations and no quotes, so the guided citation steps do not apply. `<OUT_DIR>` is `<TEMP_DIR>/one-shot`.

0. **Check that a run can start, before asking anything.** Find the document's file path (the attachment's path, or the file the request names). Run `uip login status --output json`. When there is no file path, `uip` or `node` does not respond, `Data.Status` is not `Logged in`, or `Data.ExpirationDate` is less than 20 minutes away (a run can take 15, and the script refuses a login that would expire during it), say which in one sentence and fall back (step 4); the user can log in with `! uip login` and ask again. Do not ask for the profile or create the project first.
1. **Ask for the profile once; its answers are the go-ahead.** IXP derives the inputs and structure itself, so these answers are all it takes. Use the Framing decision question as the query and show it in the question text; do not ask for it. Before asking, find the project (uipath-rules Quick Start, step 1). Quick draft replaces the project's `.dmn`, so when that step needs the user's choice between updating a project that has rules and creating a new one, add that question to this call. One AskUserQuestion, at most four questions, then run right after it with no separate confirmation. State in the question text that answering starts a billed run, uploads the document to the chosen folder, and deletes the upload afterwards. Ask again only when an answer leaves a profile field missing or invalid. State the profile in one line before the run.
   - **Outcomes.** Each as `Label[:polarity[:operator]]`: polarity `positive`, `negative`, or `neutral`; operator `any`, `all`, or `first`; polarity defaults to `positive`; a label cannot contain `:`. Propose them from the request, including an outcome for insufficient information (extraction rule 10), such as `Refer:neutral`.
   - **Score bands**, only when the decision is scored: `MIN-MAX=Outcome`, lowest first, inclusive integers, no gaps or overlaps, `5-` is the open top band; every band's outcome is an outcome label.
   - **Orchestrator folder.** The run needs `IXPModels.Create` there. Run `uip or folders list --output json`; propose the `Personal` folder as option 1, then the other `Standard` folders by `Path`. Never invent a folder key.

   Always send `--notes`: IXP is told only the outcome labels, so the notes are the one place it learns what an outcome means, and it emits a row for an outcome only when a rule in the policy votes for it. Write one line per outcome from the user's own answers, always including `<LABEL>: use when the information needed to decide is missing or unclear` for the insufficient-information outcome, plus any fact the user stated (jurisdiction, line of business, an assumption). Never put policy interpretation there. Keep the query at 2000 characters or fewer and the notes at 8000 or fewer.
2. **Use the project found or chosen, then run the one command.** `<PROJECT_DIR>` is the project from step 1: an existing one that holds the placeholder, the one the user chose to update, or a new one created as in Inputs and structure ([guided-guide.md](guided-guide.md)). Never create a second project when a usable one is there. Then run `one-shot.mjs` once. It checks the profile and login, runs IXP, writes the returned DMN over the project's `.dmn`, and runs `uip rules refresh` and `validate`. Do none of those steps by hand. It prints one JSON object; read stdout only.
   ```bash
   node "<SKILL_DIR>/scripts/extraction/one-shot.mjs" --project-dir "<PROJECT_DIR>" --file "<DOCUMENT_FILE>" --out "<OUT_DIR>" \
     --folder-key "<FOLDER_KEY>" --query "<QUESTION>" --outcome "<LABEL>:<POLARITY>:<OPERATOR>" --notes "<TEXT>"
   ```
   Add `--check` to validate the profile, login, and project without a run, one `--score-band "<MIN>-<MAX>=<LABEL>"` per band when they apply, and `--profile <NAME>` for a named `uip` login.
   - Exit 0, `status` `completed`: the DMN is written and valid.
   - Exit 1, `status` `completed-with-diagnostics`: the DMN is written but `validate` failed. Repair `diagnostics` in the written `.dmn` (uipath-rules critical rule 7).
   - Exit 1, `status` `error`: `stage` names where it stopped. A `run_id` in the result means a billed run had started: say so, and never start another. When `fallback` is `true`, follow step 4. When it is `false` (IXP rejected the profile or attachment), show the `error`, ask once whether to change the profile, and otherwise follow step 4.
   - Exit 2: a usage or project error. Fix what the `error` names and run `--check` again.
   - An expired or missing login: ask the user to run `! uip login`; never run it yourself.
3. **Finish, shortened.**
   - Run the uipdm check (Finish step 4). Run the sampled runs (Finish step 5, [guided-guide.md](guided-guide.md)) only when the request asked for them or the user asks after the summary.
   - Read the written `.dmn`: the `inputData` names, the `allowedAnswers` of the `policy_decision` decision. Show the inputs and outcomes next to the Framing profile. A difference is a question to the user, never a silent edit.
   - **An empty `policy_decision` is not a defect.** IXP's DMN follows its own hit policy, so a sampled run that returns no outcome for the omitted-input set is how IXP reports insufficient information. Extraction rule 10's default row does not apply to this DMN: add no row and no outcome to `policy_decision`, and tell the user what the result means for the consumer (the standard DMN meaning of the table's `hitPolicy`).
   - Repair only a FEEL evaluation error from a sampled run (uipath-rules critical rule 7), and only in the failing condition, as the smallest change that keeps its meaning; a missing list input must evaluate without an error and without becoming `met`. Write no XML comments (extraction rule 6).
   - Skip `resolve-refs.mjs` and the clause-coverage check: the `uipdm:sourceRef` entries carry `page`, `blockId`, and `box`, with no quote, and no `document.md` was made.
   - The summary follows "State the limits" in [guided-guide.md](guided-guide.md), and adds: the review level `Quick draft (IXP)`, the profile used, that the rule was generated from the base document only and not checked clause by clause, what an empty result means for the consumer, which expression was repaired and that IXP wrote the original (when one was), and that no supporting document was applied.
   - Do not ask about, or offer, amendments or other documents. If the user brings one later, edit the `.dmn` directly (uipath-rules, Editing an Existing Rule).
4. **Fall back.** Fall back when the script reports `fallback: true`, when `fallback` is `false` and the user declines to change the profile, when the user asks for the guided flow, or when login is missing and the user will not log in. Say in one sentence what failed (the `stage` and the `error`, with no token and no URL), and that the guided extraction continues at `Ask me only when unclear`; the user can ask for `Every section` at any time. Read [guided-guide.md](guided-guide.md) and resume at Intake with the Framing answers and the outcomes the user gave; do not re-ask them. Never run IXP again for this request.
