# Package Doc and Tool Errata — TEMPORARY

The owning skill's contract reads the installed package's per-activity doc for every activity kind a build uses ([execution-guide.md § 2.2](execution-guide.md)). **Precedence.** While the installed doc still says what a row's second column quotes, the row wins, because it was checked against the activity's source and a validate or build. Once the doc carries the corrected text, the doc wins and the row is obsolete. Check the installed doc every run: the version a project pins decides which text it ships.

## `UiPath.System.Activities` — docs shipped with 26.10.1 and earlier

| Activity | Installed doc says | The activity does |
|---|---|---|
| Get Asset, Input Dialog, Multiple Assign | the example sets an untyped argument as an attribute: `Value="[assetValue]"`, `Result="[status]"`, `<ui:AssignOperation To="[firstName]" Value="[36]" />` | An attribute on an untyped `InArgument` / `OutArgument` fails to load (`Set property '…GetRobotAsset.Value' threw an exception`), whatever the expression. The argument goes in element form with its type: `<ui:GetRobotAsset.Value><OutArgument x:TypeArguments="x:String">[assetValue]</OutArgument></ui:GetRobotAsset.Value>`. Multiple Assign's assignments also sit in an explicit `<scg:List x:TypeArguments="ui:AssignOperation">`: directly under `AssignOperations` they follow the property's default empty assignment, which fails validation (`'To' argument is required in assign operation number '1'`) |
| Log Message, Message Box | the example sets `Message` / `Text` (`InArgument<Object>`) as an attribute | In a C# library, the attribute form makes every C# workflow that calls a library activity holding it, and has a C# expression of its own, fail validation, build and pack (`Only one language requiring compilation is allowed per definition`), while the library validates, builds, packs and runs. Write the value in element form: `<InArgument x:TypeArguments="x:Object"><CSharpValue x:TypeArguments="x:Object">"text"</CSharpValue></InArgument>` |
| Add Log Fields | fields "persist for the lifetime of the workflow execution until explicitly removed" | A field added in an invoked workflow ends when that workflow returns; one added in the entry workflow is on the messages of every workflow it invokes, during the invoke and after it. A field of the whole run is added in the entry workflow |
| Set Transaction Status | `Output` and `Analytics` take inline key-value data, with no limit on the keys | A key named like one of the activity's own arguments (`Status`, `Reason`, `Details`, `ErrorType`, `TransactionItem`, …) fails validation (`A variable, RuntimeArgument or a DelegateArgument already exists with the name '<key>'`); such keys go through `OutputVariable` or `AnalyticsVariable`, which accept any key |

## `UiPath.Excel.Activities` — docs shipped with 3.7.2 and earlier

| Activity | Installed doc says | The activity does |
|---|---|---|
| Use Excel File (`ExcelApplicationCard`) | nothing on a sheet reference the workbook lacks | A sheet reference through the scope's workbook reference (`Excel.Sheet("<name>")`) to a sheet the workbook lacks raises no error: a cell read returns no value, a range read one row of `DBNull` cells, and the next save writes the sheet, empty. Where a missing sheet must fail, check the name against the workbook's sheet names before the first reference to it |

## `UiPath.MicrosoftOffice365.Activities` — docs shipped with 3.12.11 and earlier

| Activity | Installed doc says | The activity does |
|---|---|---|
| Get Email List; coded `GetEmails` | nothing on `OrderByDate`, which the default XAML carries (`OrderByDate="NewestFirst"`); the coded doc says `OrderBy.OldestFirst` returns the oldest emails first | Neither applies the order: no value changes the order of the returned emails or which ones `MaxResults` / `maxResults` keeps. To process the oldest email first, retrieve the list and sort it by `ReceivedDateTime` (`Item.ReceivedDateTime` on a coded `IMail`) |
| Get File List, Upload Files | declare the `Result` / `AllResults` variable as `scg:List(umo365fm:O365DriveRemoteItem)` | Both are `OutArgument<O365DriveRemoteItem[]>`: bind a `umo365fm:O365DriveRemoteItem[]` variable. A `List` variable fails: bound in element form it fails to load (`Set property '…Result' threw an exception`), bound as an attribute it fails to compile (`BC30311`) |
| Set Email Categories | `CategoriesToAssign` / `SpecificCategoriesToRemove` only as a VB flat attribute, since an `InArgument` cannot be typed `String[]` | `<InArgument x:TypeArguments="s:String[]">` works in VB and C# projects; only `x:String[]` fails to load |

## `UiPath.UIAutomation.Activities` — docs shipped with 26.10.10 and earlier

| Doc | Installed docs say | What the build does |
|---|---|---|
| Target System (§ Window Selector), `NAppAttachMode` | the attach mode decides which windows inner activities search: `ByProcessName` "all windows with the same process name", `ByInstance` the whole instance, its windows ranked by the window selector's `title` | Treats a browser card as working in one tab under every attach mode: an inner activity whose window selector is a web selector searches the tab of the card's `InUiElement`, else the tab the card attached to, and the selector's `url` and `title` are not compared with it |
| Check App State (`NCheckState`) | Two branches, "Target appears" and "Target does not appear", with no names for the other modes; `Exists` is "the detected state of the target" | The branches follow `Mode`. `WaitDisappear`: "Target disappears" in `IfExists`, run when the target is gone or goes within `Timeout`, and "Target does not disappear" in `IfNotExists`, run after the whole `Timeout` when it is still there. `WindowNotActive`: "Window not in foreground" in `IfExists`, run when the target's top-level window leaves the foreground or the target goes within `Timeout`, and "Window still active" in `IfNotExists`. `Exists` is `false` after `IfExists` and `true` after `IfNotExists` in these two modes. With `CheckVisibility`, `WaitDisappear` counts a present but hidden target as gone, and `WindowNotActive` counts a present target as gone only once it is hidden and its window has left the foreground. Work for "the element went" goes in `IfExists`, work for "still shown" in `IfNotExists` |

## Tools — defects seen in builds, until fixed

Each row was met in a build that validated and packed, or in a live search against the application; the third column is what that build did instead. Versions: rechecked with `uip` 1.206.0, except the Flow runtime rows (last seen with Flow builder SDK `@uipath/maestro-builder-sdk` 6.15.3) and the `uip tm testcases link-package` and Data Fabric entity rows (last seen with `uip` 1.204).

| Tool | Defect | What the build does |
|---|---|---|
| Flow runtime | A flow or child-flow input named `source` arrives empty, with no diagnostic | Names the input otherwise (`sourceName`) |
| Flow runtime, Data Fabric read | An `in` filter with a list value fails (`valueList[0] … System.String`) | Reads without that filter and narrows the rows in a script step |
| `uip api-workflow run` | Prints `fast-json-patch MODULE_NOT_FOUND` stack traces when the working directory has no `node_modules`; the result is correct | Judges the run by its envelope |
| `uip tm testcases link-package` | Requests a page larger than 100 and fails with HTTP 400 (`Page size cannot be greater than 100`) | Creates each test case and links it with `testcases link-automation`, one by one |
| `uip rpa run` | Prints a Log Message at Fatal as `[Verbose]`; Orchestrator records it as Fatal | Reads a log line's level from the workflow, not from the printed tag |
| `uip rpa data-fabric-entities install` and `list`, `UiPath.UIAutomation.Activities` 26.10.8 | Fail with `MissingMethodException` (`EntitiesContext.set_EntitiesContainer` on install, `IEntitiesInstallParams.GetSelectedEntities` on list) in a project that references UI Automation; the same commands succeed in a project without it | Installs the entities before UI Automation is added to the project. A later install runs in a scratch project that references no UI Automation package, with the project's namespace (the install's namespace option); the build then copies that project's service document (`.entities/EntitiesStore.json`) and its `project.json` `entitiesStores` entry into the project, and the entity types compile |
| `uip rpa build`, `UiPath.DataService.Activities` 26.10.1 | Warns `Could not resolve arguments for XAML workflow … violates the constraint of type 'TEntity'` on a workflow holding an entity activity once a coded workflow calls it through `workflows.<Name>()`, though the entity type meets the constraint; that call then fails the build's own compile (`CS1061` on `WorkflowRunnerService`) while the build reports success; packing prints the same error and reports success too. `uip rpa run` compiles and runs the same call | Accepts the warning; a coded caller of such a file is checked by a local run, not by the build's or the pack's result |
| `uip rpa build`, `uip rpa pack` | Report success for a project whose coded file's `CodedWorkflow` base class does not resolve (`CS0246`, the file in a namespace other than the project's), which `uip rpa validate` of that file reports; any other unresolved type fails the build | Validates every coded file on its own; the build's success does not cover them |
| `uip solution` | A Windows project's process resource is written with `targetFrameworkValue` `Portable`, the process specification's default, not the project's target framework; `resources edit --patch` reports success and leaves it unchanged, since the specification marks it read-only | Lists it in the solution's open items: check the deployed process's runtime before its first run. Whether a deploy takes the runtime from this value or from the package is untested |
| `uip solution resources refresh` | Declares every asset a project's bindings name as a Text asset (`stringAsset`), whatever type the Get Asset that reads it gives `Value`: a binding carries the asset's name and no type. Adding the asset with its type is refused while the Text one exists (`already exists with type stringAsset`) | After a refresh, removes by its key each asset whose Platform Dependencies type is not Text and adds it with that type (`resources add --source local --kind Asset --type Integer`); a later refresh keeps it |
| UI Automation screen link with a variable in `Arguments`, `UiPath.UIAutomation.Activities` 26.10.10 | `target-app update-definition` has no option for `Arguments`, so a variable there is written in the seed. The Object Repository screen keeps a plain variable as written, while `link-screen` writes it into the card as `string.Format("{0}", <variable>)`; a run evaluates the screen's copy, which the build never compiled: the card validates and builds, then fails with ``Arguments Expression Activity type 'CSharpValue`1 (<variable>)' requires compilation in order to run`` (``VisualBasicValue`1`` in a VB project) | Writes the variable in the seed as `link-screen` writes it: the `CSharpValue` text `string.Format("{0}", <variable>)` in a C# project, `[string.Format("{0}", <variable>)]` in a VB one |
| UI Automation element replaced with a changed expression, `UiPath.UIAutomation.Activities` 26.10.10 | A selector variable in an element's selector or semantic description is stored as a `string.Format` expression, and linking writes the same expression into the activity, so a build compiles it. After `object-repository replace-elements` changes that expression, the linked activities keep the old text and a run evaluates the element's new one, which the build never compiled: validate and build pass, then the activity fails as it starts with ``FullSelectorArgument Expression Activity type 'CSharpValue`1 (…)' requires compilation in order to run`` (`SemanticSelectorArgument` for a description; ``VisualBasicValue`1`` in a VB project) | Links every activity linked to the element again after each `replace-elements` that changes an expression in it; writes a semantic description as plain text, naming the varying part in words |
