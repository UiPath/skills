# Automation Anywhere Source Guide

Framework facts for extracting a genome from an Automation Anywhere **Automation 360** bot export (Control Room repository export, including bots migrated from Enterprise 11 by the Bot Migration wizard). Follows [source-framework-contract.md](source-framework-contract.md); pipeline: [extraction-guide.md](../extraction-guide.md); generic rules pointed to below are not restated here.

Export = a folder tree mirroring the Control Room repository: `Bots/My Tasks/<folders>/<BotName>` and `Bots/My MetaBots/<folders>/<BotName>` hold one **extension-less JSON document per bot**; `<BotName>Metadata/` folders hold the recorder's screenshots; `MyDocs/` (or `My Docs/`) holds files the bots read through `repository:///` URIs. Bot documents are small (tens to hundreds of kilobytes) but a bot line holds a base64 blob per captured UI object and the same twenty-variable dictionary on every sub-bot call, so read them through the bundled inventory script, never raw:

```bash
# Extract mode — read the export from a scratch folder
python3 <SKILL_DIR>/scripts/a360-export-inventory.py profile "<EXPORT_DIR>" --out "<WORK_DIR>"
python3 <SKILL_DIR>/scripts/a360-export-inventory.py cards   "<EXPORT_DIR>" --out "<WORK_DIR>"
python3 <SKILL_DIR>/scripts/a360-export-inventory.py dump    "<EXPORT_DIR>" "<BOT_NAME>" --compact   # one bot, line by line; drop --compact to see disabled subtrees in full
python3 <SKILL_DIR>/scripts/a360-export-inventory.py targets "<EXPORT_DIR>" --out "<WORK_DIR>"   # windows + captured controls with decoded properties and the action applied
python3 <SKILL_DIR>/scripts/a360-export-inventory.py data    "<EXPORT_DIR>" --out "<WORK_DIR>"   # bot inventory with call edges + data sources, for the step-map check
# Execute mode (migration preflight) — derive the catalogs into the build's working folder
python3 <SKILL_DIR>/scripts/a360-export-inventory.py targets "<EXPORT_DIR>" --out "<BUILD_DIR>/migration/source"
python3 <SKILL_DIR>/scripts/a360-export-inventory.py data    "<EXPORT_DIR>" --out "<BUILD_DIR>/migration/source"
python3 <SKILL_DIR>/scripts/genome-step-map.py "<GENOME.md>" --processes "<BUILD_DIR>/migration/source/a360-process-data.json" --recordsets "<BUILD_DIR>/migration/source/a360-data-sources.json" --out "<BUILD_DIR>/migration/source"
```

`profile` writes identity, packages, folders, command vocabulary, per-bot summary, call graph, roots, credential references, windows, capture counts, application launches, mail, database and file commands, evidence density and migration plumbing; `cards` one compact card per bot (description, inputs, outputs, callers, callees in order, windows, captures, conditions, loops, database, keystrokes, error handling, evidence); `dump` one bot in editor order with every attribute rendered (`--compact` folds disabled subtrees to one line and shortens log and delay lines). Read profile and cards in full; dump every bot the genome covers — compact first, full only where a folded subtree matters. `targets` writes the UI target catalog (`a360-targets.json` + `.md`: window variables, captured controls with decoded object properties, keystroke commands — § UI Target Locators); `data` the bot inventory (`a360-process-data.json`, a **list** with id, path, folder, inputs, outputs, call edges with their argument bindings) and the data sources the bots read and write (`a360-data-sources.json` + `.md` — § Test Data). Which mode reads what, and why nothing is written beside the genome: [genome-format-guide.md § Source Map](../genome-format-guide.md) and [source-migration-guide.md § Migration preflight](../source-migration-guide.md).

Automation 360 exports carry no numeric object ids: a bot is identified by its repository path, and names repeat across folders (`Main` in two projects, a MetaBot logic and the task that calls it named alike). The script derives a stable six-digit id from the path (CRC-32 folded into 100000–999999; the same export yields the same ids) so Source Map rows carry `` `Name` (id) `` and `genome-step-map.py` resolves them.

## Detection

| Signal | Meaning |
|---|---|
| Folder containing `Bots/` whose files are extension-less JSON documents with top-level `nodes`, `variables`, `packages` (and `triggers`, `breakpoints`, `properties`, `migrationJournalReviewIds`, `workItemTemplateName`) | Automation 360 Control Room export. Multi-component: a repository folder holds a **root task bot plus the sub-bots it runs**, so the export is a **process genome** whose components are the bot groups of § Component Detection. |
| `Bots/My MetaBots/…` folders | Enterprise 11 MetaBots converted by the Bot Migration: their logic blocks are now ordinary bots, each still one reusable UI capability |
| `Bots/My Tasks/…` folders | Task bots (v11 `.atmx` converted, or authored in Automation 360) |
| `<BotName>Metadata/` beside a bot, full of `*.png` | Recorder screenshots (`screenshotMetadataPath` / `thumbnailMetadataPath` inside capture and region values); evidence of what was captured, never logic |
| `migrationJournalReviewIds` non-empty, `LegacyAutomation` package, variables named `m-*` / `M-*` / `Loop-*` / `Error-*`, `Prompt-Assignment`, `my-list-variable` | Bot Migration output: the bot was converted from Enterprise 11 (§ Framework Pitfalls) |
| `packages[].version` | Package build dates identify the Automation 360 release the export was taken from (e.g. `Recorder 2.16.0-20231101-…`) — the version the Source Map states |
| `properties.automationPriority`, `properties.botCodeVersion` | Run priority and the bot's own edit version; identity only |
| `MyDocs/*.xml`, `MyDocs/*.xlsx` | Configuration files the bots read through `repository:///` paths; the only run-time data present in the export |

A single bot file with no `runTask` command is one **component** (component genome). An export missing `Bots/` but holding the JSON documents in one folder is still an export; the repository paths are then the file names, flagged `*[Inferred]*`.

## Inventory and Exclusions

| Pattern | Contents | Use |
|---|---|---|
| `Bots/**/<Bot>` (no extension, JSON) | One bot: `variables[]`, `nodes[]` (tree with `children` and `branches`), `packages[]`, `properties`, `triggers[]` | Steps, control flow, call graph, interface, targets |
| `nodes[].variables` … `variables[]` fields `name`, `type` (STRING, NUMBER, BOOLEAN, LIST, DICTIONARY, RECORD, DATETIME, WINDOW), `subtype`, `input`, `output`, `readOnly`, `defaultValue` | Bot interface (`input`/`output` flags) and constants (`readOnly`, literal defaults); WINDOW variables carry the recorded window (`window.name` title with `*` wildcards, `window.class`, `window.path` executable) | Interface, Target Applications, target catalog |
| `<Bot>Metadata/*.png` | Recorder screenshots of captured controls and screen-change regions | Evidence only; never read for logic |
| `MyDocs/`, `My Docs/` | Configuration XML and workbooks addressed by `repository:///Automation Anywhere/Bots/…` URIs | Configuration Questions defaults; data sources |
| `triggers[]` | Bot-level triggers (empty in exports of scheduled bots — schedules live in the Control Room, not the export) | Deployment note |

Excluded from logic: nodes with `disabled: true` **and their whole subtree** (the editor shows them greyed; the runtime skips them — `dump --compact` folds them to one line); `Comment` nodes whose text is a separator (`====`, `----`, `||||`) or a migration placeholder (`Please enter the commands to handle errors.`, `EndIf`, `Please enter the conditional commands here.`); `MessageBox` nodes (debugging left-overs — in a production export they are almost all disabled; an enabled one is a pitfall, § Framework Pitfalls); `LegacyAutomation.getKeystrokesDelay` (computes the delay the following keystroke command uses); `Delay.delay` (timing → Error Handling wording, never a step); `LogToFile.logToFile` (the run's own log — § Evidence; its **message text** is the author's step narration and is read for wording); `Screen.captureDesktop` (screenshot on error — § Evidence); `String.assign` of a `m-string-start-in-path*` variable (migration plumbing that feeds the next command's path); `.LegacyAutomation:parseVariableOperation` re-assignments of the variable just assigned (a no-op the migration inserted after every assignment).

## Component Detection

Automation 360 has one artifact type: the bot. Components come from the **repository folders and the call graph**, not from file types:

| Construct | Component type | Skill | Rationale |
|---|---|---|---|
| The root task bot (never called by an enabled `runTask`) plus the task bots in its folder that only it and its siblings call (initialisation, mail intake, data filtering, navigation, notification, cleanup) | One **RPA process** (REFramework-style: initialise → get work → process → report) | `uipath-rpa` (Process project) | One deployable unit in Automation 360 (the root is what the Control Room schedules); the sub-bots are its phases, not products of their own |
| A `My MetaBots/<Product>/<MetaBot>` folder: the logic blocks of one migrated MetaBot (login, navigate, search, change a value, read a popup, read a title) | One **UI library** for that application | `uipath-rpa` (Library project, one public workflow per logic bot) | A MetaBot is Automation Anywhere's reusable application library; its logics are invoked from several task bots with a fixed argument set (the MetaBot input/output variables) |
| A `Reusable_Components` (or `Common`, `Shared`) folder of bots called from several processes' roots — application launchers, shared exception loggers | One **common library** | `uipath-rpa` (Library project) | The customer maintains it as shared code; other processes of the export or of the tenant depend on it |
| Bots reachable only through **disabled** `runTask` commands, or referenced by a path no file in the export matches | Dead calls / unresolved | Source Map only | Superseded copies (`ToDataFilter` vs `TODataFilterTask`) or bots outside the export |
| `triggers[]` with an event or schedule trigger | Entry point of the process component | Deployment → triggers | Rare in exports; the Control Room schedule is the usual trigger and is not exported |

Every construct maps to `uipath-rpa`: Automation 360 has no flow, agent or API-workflow equivalents in an export; a `runTask` chain is workflow invocation, not orchestration. When a root does nothing but call other roots each with its own schedule, consider one process per root and a coordinating Flow `*[Inferred]*`.

## Signals — Bot

`profile` and `cards` surface these; `dump` shows them per line. Line numbers are the editor's (every node including `else`, `elseIf`, `catch`, `finally` branches counts one line) — the `Error-LineNumber` a catch block logs refers to them.

| Signal | Path | Tells you | Example |
|---|---|---|---|
| File path below `Bots/` | export tree | Bot identity and folder (process vs MetaBot vs shared) | `My Tasks/CCAmerica/AutoCompTO_Excel/MainTask` |
| First `Comment` node, or the first comment starting `Description:` | `nodes[0..]` | Author's purpose statement; verify against the steps | `Metabot logic to change department code in LARA application` |
| `variables[]` with `input: true` / `output: true` | top | Bot interface. **Migrated bots flag almost every variable in/out** because the v11 runtime shared them; the real contract is the subset the callers bind in `taskbotInput` / `taskbotOutput` — read the call, not the flags | |
| `variables[].defaultValue` literal on a non-window variable | top | Constants and hardcoded defaults → Configuration Questions (`ConfigFilePath`, mail sender, department code, a test transport-order number) | `strDept` default `1816` |
| `TaskBot.runTask` — `taskbot.taskbotFile.string` (`repository:///…/Bots/<path>`), `taskbotInput.dictionary[] {key, value}`, `taskbotOutput.dictionary[]`, node `returnTo` (a DICTIONARY variable, or a map of callee output → caller variable), `continueOnError`, `repeatOption` | node | **Call-graph edge** and the data passed each way. `continueOnError: true` = the caller carries on when the sub-bot fails (its own error flag decides) | |
| `If.if` / `If.elseIf` / `If.else` with `condition` attributes of type CONDITIONAL; several conditions joined by an `operator` attribute (`AND` / `OR`) | node + branches | Business rules and routing. Condition kinds: `legacyConditionVariable` and `stringVariable` (`variable`, `operator` EqualsTo / DoesNotEqualTo / EQ / INCLUDE / NOTINCLUDE / GreaterThan / GreaterThanOrEqualTo / LTE, `value`, `matchCase`), `numberVariable`, `booleanVariable`, `windowExists` / `windowTitleExists` / `windowTitleDoesNotExists` (`window`, `waitTimeout`), `fileExists` / `fileNotExists` / `folderDoesNotExists` (`waitTimeout`), `hasExtension` (`IN_SET` list), `applicationRunningExists`, and a **Recorder `capture` used as a condition** = "the control exists within N seconds" | `if "$strErrorPopupText$" INCLUDE "no records"` |
| `Loop.loop.commands.start` with `iterator` (ITERATOR): `loop.iterators.times` (`times`), `iterators.resultset` (database `session`), `loop.iterators.email` (`sessionName`, `folder`, `readStatus` UNREAD/READ/ALL, `from`, `subject`), `loop.iterators.files` (`folderPath`), `list.iterators.list`; `loop.commands.break` / `continue` | node | Iteration and retry loops. A `times` loop whose body ends in `break` on success is a **retry with N attempts**; a `times` loop whose body re-queries "the first pending row" and processes it is a **work-item loop** | `for times(times="$LOGIN_RETRY.String:toNumber$")` |
| `ErrorHandler.try` with `catch` branch (`exceptionType` BotException, `returns` errorMessage / errorLineNumber into variables, `continueOnError`) and `finally`; `ErrorHandler.throw`; `TaskBot.stopTask` | node + branches | Error handling per step; `stopTask` ends the bot (the caller's `continueOnError` and error flag decide what happens next); the migration's `finally` + `if M-IsBotExecutedSuccessfully = false → throw` marks the bot Failed in the Control Room | |
| `Recorder.capture` — `uiObject` (UIOBJECT: `technologyType`, `controlType`, `criteria`, base64 `blob`, `uiObjectWindow`), action attribute (`textboxAction` / `buttonAction` / `clientAction` / `labelAction` / `passwordtextAction` = LEFTCLICK / CLICK / DOUBLECLICK / SETTEXT / GETPROPERTY), `value` (typed text or the property to read: Value / Name / HTML InnerText), `valueCV` (CREDENTIAL typed from the vault), `typeOfInput` (VALUE / CREDENTIAL), `runInBackground`, `wait`, `returnTo` | node | UI action on one control; technology and window decide the UiPath tag ([automation-anywhere-selectors-guide.md](automation-anywhere-selectors-guide.md)). GETPROPERTY into a variable is a **read** (title, popup text, cell value); SETTEXT with key tokens in `value` (`$x$[TAB]`) is a **type-and-confirm** (§ Composite actions) | |
| `Keystrokes.Keystrokes` — `windowValue` (WINDOW), `stringToType` with tokens `[F5]`, `[ENTER]`, `[CTRL DOWN]S[CTRL UP]`, `[ALT DOWN]i[ALT UP]`, `[DOWN-ARROW]` | node | Keys to a **window**, not a control; the preceding capture says which control has focus (§ Composite actions) | |
| `Window.activateWindow` / `maximizeWindow` / `closeWindow` / `SetTitle`; `Wait.waitForWindow` (OPEN/CLOSE, timeout, throw flag); `Wait.waitForScreenChange_V1` (region + screenshot) | node | Session handling; a wait-for-window with `isThrowException: false` is an optional presence check | |
| `Browser.openbrowser` (`browser` EDGE / INTERNET_EXPLORER, `url`, `openOption` NEW_WIN / NEW_TAB / EXISTING_TAB, `timeoutValue`) ; `Application.runApp` (`filePath`, `parameters`, `startInPath`) | node | Application launch. **`runApp` of `taskkill` (`/f /im <exe>`) is a forced application close** — Error Handling and cleanup wording, never a "run an application" step; `runApp` of `iexplore.exe` / `msedge.exe` with a URL is "open the URL in <browser>" | `taskkill /f /IM java.exe` |
| `Email.emailConnect` (`serverType` EWS / EMAIL_SERVER, `exchangeService`, `authType` Interactive, `clientIdInteractive` / `tenantIdInteractive` / `ewsUsernameInteractive` CREDENTIAL, or `serverHost` / `port` / `protocol` IMAP / `username` / `securedPassword`), `loop.iterators.email`, `Email.saveAttachment` (`folderPath`), `Email.moveEmail` (`sourceFolder`, `destinationfolderPath`, `readStatus`, `subject`, `from`), `Email.sendMail` (`toAddress`, `cc`, `subject`, `message`, `bodyFormat`, `attachmentsFilePath`, plus the server block), `Email.closeEmail` | node | Mailbox access → Target Applications (Exchange Online / the mail server) and credential assets; the loop's `readStatus` and `folder` are the intake rule | |
| `Database.connect` (`connectionURL` — an OLEDB string; `Provider=Microsoft.ACE.OLEDB.12.0;Data Source=<xlsx>;Extended Properties="Excel 12.0 Xml;HDR=Yes"` means **the "database" is an Excel workbook**), `Database.sqlQuery` (`query`, `doExport` + `filePath` to CSV), `Database.insertUpdateDelete`, `Database.disconnect`, `iterators.resultset` | node | Excel read/write through SQL: `[Sheet1$]` is a worksheet, `[Column]` a header. Read the WHERE clauses as **business filters** and the UPDATE/INSERT as the record the process writes back | `Select DISTINCT [Transport Order No] … Where [Transport Status] IN ('Started','Sent','Generated')` |
| `Excel_MS.OpenSpreadsheet` / `SwitchToSheet` / `GoToCell` / `SetCell` / `GetSingleCell` / `CreateSpreadsheet` / `CloseSpreadsheet` | node | Direct workbook operations. `SetCell` of a formula followed by `GetSingleCell` on the same cell is a **computed read** (the idiom `=MID(CELL("filename",A2),…)` reads the *sheet name*) | |
| `File.*` (`copyFiles`, `deleteFiles`, `renameFiles`, `createFile`), `Folder.createFolder`, `loop.iterators.files` | node | File lifecycle: intake folder → processed → archive by date; paths come from configuration variables | |
| `XML.startSession` (`filePath` `repository:///…`) / `getSingleNodeV2` (`xPath`) / `endSession` | node | Configuration read from a file **inside the export** — its values are the Configuration Question defaults | `//Configuration/RootPath` |
| `String.*` (`assign`, `replace`, `beforeAfter`, `split`, `subString`, `uppercase`, `reverse`), `List.*`, `Record.assign`, `Number.assignToNumber`, `Boolean.assign`, `Datetime.toString`, `System.systemInformation` (USERNAME) | node | Data preparation. `beforeAfter` on a subject or file name is a **parsing rule** (company code = text between `-` and `:`); `replace` of a placeholder (`FileName`, `{0}`, `USERNAME`) is **templating**; a `reverse` / `beforeAfter` / `reverse` sequence splits a path into folder and file | |

| `Comment` text `In below action, legacy bot referred following: Credential name=<v11 credential>, attribute name=<attr>` | node | The Enterprise 11 Credential Vault entry the action used before migration; pairs with the CREDENTIAL value the action carries now → one credential asset per account (§ Platform Resources) | |

### Step vocabulary → behaviour

| Command | Genome wording |
|---|---|
| `TaskBot.runTask` | Invoke sub-bot (call-graph edge; in a UiPath process, invoke workflow; across components, invoke the library workflow) |
| `If` family with a variable condition | "If {variable in business terms} {is / is not / contains / exceeds} {value}, then …; otherwise …" ([genome-format-guide.md § Business Rules](../genome-format-guide.md)); `INCLUDE` = contains, `NOTINCLUDE` = does not contain, `EQ` with `matchCase` = is exactly |
| `If windowExists` / `windowTitleExists`, `Wait.waitForWindow` | "If the {dialog or window} appears within N seconds, …" — optional dialog handling |
| `If fileExists` / `folderDoesNotExists` | Pre-condition on the file system ("create the folder when missing") |
| `Loop times` ending in `break` on success | "Retry up to N times" — Error Handling |
| `Loop times` over a count read from a query, each iteration fetching the next pending row | "For each pending {record} …" — the work-item loop |
| `Loop resultset` | "For each row returned by {query in business terms}" |
| `Loop email` | "For each {unread / all} message in {folder} [from {sender}]" |
| `Loop files` | "For each file in {folder}" (+ the extension filter the body applies) |
| `Recorder.capture` LEFTCLICK / CLICK | Click {control}; DOUBLECLICK = "double-click {control} to open / enter the cell" |
| `Recorder.capture` SETTEXT (`typeOfInput` VALUE) | Enter {value} into {field}; with a CREDENTIAL value: "enter the {account}'s user name / password from the credential asset" — never a literal |
| `Recorder.capture` SETTEXT whose `value` ends in a key token (`[TAB]`, `[ENTER]`) | **Composite** — type and confirm (§ Composite actions) |
| `Recorder.capture` GETPROPERTY `value=Value` / `Name` / `HTML InnerText` | Read {what the control shows} into {output} — window title, popup message, cell value, page heading |
| `Recorder.capture` as an If condition | "If {control} is present within N seconds" |
| `Keystrokes.Keystrokes` | **Composite** — keys to the focused control or the application's shortcut (§ Composite actions) |
| `Browser.openbrowser`, `Application.runApp <browser> <url>` | Open {URL} in {browser} (new window / tab) |
| `Application.runApp taskkill /f /im <exe>` | Force-close {application} — cleanup or recovery, not a step of its own |
| `Window.closeWindow`, `Window.activateWindow`, `Window.maximizeWindow` | Close / bring to front / maximise {window} |
| `Window.SetTitle` | Rename the window the recorder matches (a run-time locator rewrite) → Source Map note only |
| `Email.emailConnect` + loop + `saveAttachment` + `moveEmail` | Intake: "read {unread} messages in {folder} of {mailbox account}, save attachments to {folder}, move handled messages to {archive folder}" |
| `Email.sendMail` | Send {which notification} to {recipients} with {subject template}, {body template}, {attachments} |
| `Database.connect` to an OLEDB Excel string + `sqlQuery` | Read {rows matching the WHERE clause in business terms} from sheet {name} of {workbook} |
| `Database.insertUpdateDelete` | Write / update {columns} of the {record} row in {workbook} |
| `Database.sqlQuery` with `doExport` | Export {rows} to CSV {file} |
| `Excel_MS.*` | Open / create {workbook}, write headers, read a cell — with the sheet-name idiom read as "find the sheet whose name contains {text}" |
| `File.*`, `Folder.*` | Move / copy / delete / rename {file} between the intake, processed and dated archive folders |
| `XML.getSingleNodeV2` | Read {setting} from the configuration file |
| `String.*` parsing | The parsing rule in business terms, with the delimiters kept ("the company code is the text between `-` and `:` in the subject") |
| `String.replace` of `{0}` / `{1}` placeholders in a template | "Fill the {which} template: {0} = date, {1} = count, …" |
| `LogToFile`, `Screen.captureDesktop`, `MessageBox`, `Delay`, `Comment`, `Step`, `getKeystrokesDelay` | Not steps (§ Evidence, Inventory exclusions) |
| `TaskBot.stopTask` | "Stop the bot here" — the caller reads the error flag; Error Handling wording |
| `ErrorHandler.throw` in the migration's `finally` | Marks the run Failed in the Control Room when any handled error occurred → Error Handling § Global |

### Value syntax

`$name$` a variable; `$name{key}$` a dictionary or record field (`$Loop-Email-Response-1{emailSubject}$`, `$Loop-Files-1{extension}$`); `$name[0]$` a list element or a record column by index; `$name.Package:function$` a value transform (`.String:toNumber`, `.Number:toString`, `.String:uppercase`, `.LegacyAutomation:getIncrementedNumber`, `.LegacyAutomation:getCellByIndexOrName("SenderEmail")`); `$@Name$` a Control Room **global value** (`$@AABasePath$`, `$@AAE_EmailSettings_host$`); `$System:Name$` a system variable (`AATaskName`, `Year`, `Month`, `Day`, `Hour`, `Minute`, `Second`, `AATaskExecutor`). A STRING value carries `expression` when it references variables and `string` when literal; read `expression` first. `FILE` values are `file://<path>` or `repository:///Automation Anywhere/Bots/<path>`; `%20` and `%3B` are URL-encoded. CREDENTIAL values are references (`lockerName` / `name` / `attributeName`), never secrets. Literal values are the defaults for Configuration Questions. Never copy a literal assigned into a variable whose name contains `password`, `pwd`, `secret` or `token`: bots carry such literals (pitfall 9) and the inventory script redacts them.

### Composite actions (no single UiPath equivalent)

Automation 360 records one command per interaction, but several commands bundle behaviour the genome must spell out ([genome-format-guide.md § Workflow](../genome-format-guide.md)); execution builds the pattern named in the last column ([source-migration-guide.md § Composite interactions](../source-migration-guide.md)). `targets` records every capture with its action and value so execution sees the contract next to the locator.

| Command | Parameters that define the interaction | Workflow substep wording | Pattern |
|---|---|---|---|
| `capture` SETTEXT with a key token inside `value` (`$strTOStatus$[TAB]`, `$vLARAUrl$[ENTER]`) | typed text, confirm key | "Enter {value} into {field} and confirm with Tab / Enter" — the confirm is part of the entry (a Forms field commits on Tab) | Type-and-confirm (Type Into with the key token, verify the committed value) |
| `capture` DOUBLECLICK on a cell, then SETTEXT on the same control | control with `Index` / `Path` bound to a variable | "Double-click the {column} cell of the current row to enter edit mode, then enter {value}" | Table cell |
| `capture` with `Index="$var$"` or `Path="…\|$var$"` and a loop that increments the variable while reading `Value` | positional index driven by a counter | "Walk the {column} cells from the first row down (up to N rows) reading each value until {condition}" — the index is the row position in the Java grid; the genome states the stopping rule, never the index | Table row by content (positional fallback flagged) |
| `Keystrokes` `[F5]` / `[F11]` / `[CTRL DOWN][F11][CTRL UP]` / `[CTRL DOWN]S[CTRL UP]` / `[F4]` after a click into a field | application shortcut | The application's **function**, not the key: Oracle Forms `F5` = clear field, `F11` = enter query / clear form, `Ctrl+F11` = execute query, `Ctrl+S` = save, `F4` = exit; word it as "execute the query (Ctrl+F11)" so the build keeps the shortcut and the reader keeps the meaning | Keystrokes to the focused element |
| `Keystrokes` `[ENTER]` right after a failed click on a popup's OK button | fallback path | "Confirm the popup (OK button; Enter when the button cannot be clicked)" — one substep, the fallback in Error Handling | Keystrokes fallback |
| `Keystrokes` `[ALT DOWN]i[ALT UP]` then `[ALT DOWN]r[ALT UP]` on a Java `Security Warning` dialog, or a click on its `Run` button | dialog handling | "If the Java security warning appears, accept the risk and run (Alt+I, Alt+R; click Run as fallback)" | Option / dialog handling |
| `Keystrokes` `[DOWN-ARROW]`, `[CTRL DOWN][UP-ARROW][CTRL UP]` inside a grid | row navigation | "Move to the next row" / "return to the first record" — grid navigation the pattern replaces with a row rule where possible | Keystrokes |
| `capture` LEFTCLICK on a `PushButton` located only by `Index` / `Path` (toolbar `Index=30` close, `Index=4` search, `Index=11` clear, `Path -1\|1\|2\|2\|2\|1` save) | positional toolbar button | Name the **function** the log line beside it gives ("close the screen", "clear the screen", "save") and flag the locator positional | Coordinate / positional click (low) |
| `capture` LEFTCLICK on a `StaticText` whose `Name` is a variable (`$strMenuItemName$`) | menu node by caption | "Click the menu node named {menu item}" — a tree/menu path level | Menu / tree path |
| `capture` GETPROPERTY `Name` of a `Client` object with a popup-text name | reading a Forms alert | "Read the message of the alert dialog if one is showing" — the result drives a branch; the read is the check | Read control text |
| `SetCell` formula + `GetSingleCell` | computed read | "Read the sheet's name" (or whatever the formula computes) — never the formula | Excel read |
| `runApp taskkill` sequence (`msedge.exe`, `java.exe`, `excel.exe`, `outlook.exe`) | cleanup | "Force-close the browser, the Java application and Excel" once in Error Handling / cleanup step | Kill process |

Oracle Forms specifics the LARA bots instantiate: the application is a Java applet launched from a browser page through Java Web Start (`jp2launcher.exe`, frames `SunAwtFrame`, dialogs `SunAwtDialog`), the browser only hosts the launch page; Forms alerts are internal dialogs whose message is the accessible name of a `Client` object; grids are rows of identically named text fields distinguished by accessibility index; the status bar is a `StaticText` (`FRM-40301: Query caused no records to be retrieved`).

## Target Resolution

1. **Window variable → application.** Every UI command names a WINDOW variable; its `window.path` executable and `window.class` give the application (`jp2launcher.exe` + `SunAwtFrame` = Java Web Start application, `javaw.exe` + `#32770` = a Java runtime dialog, `msedge.exe` + `Chrome_WidgetWin_1` = Microsoft Edge, `iexplore.exe` + `IEFrame` = Internet Explorer, `OUTLOOK.EXE` + `rctrl_renwnd32` = Outlook desktop, `Explorer.EXE` + `CabinetWClass` = a File Explorer window, `CredentialUIBroker.exe` = the Windows credential prompt). The `window.name` is the title with `*` wildcards; the business application's name is the title's stable word (`LARA*`, `fulfillmentSCE*`). A window variable with empty `path` and `class` was never captured against a live window — title only.
2. **URL variables** (`LARA_DEV_URL`, `LARA_QA_URL`, `LARA_PROD_URL`, `openbrowser.url`) → Configuration Question "Which environment URL?" with the host as default; the values live in the configuration workbook, not the export, so the default is the variable's role unless a literal is present (a frame `src` in a capture — `http://lara-11g.<tenant>/LHP_appli.html` — gives the host).
3. **Mail server.** `emailConnect serverType=EWS` with `exchangeService`, OAuth `clientIdInteractive` / `tenantIdInteractive` = Exchange Online (Microsoft 365) through EWS; `EMAIL_SERVER` + `protocol IMAP` + `serverHost` = the named IMAP host; a browser login to `outlook.office365.com` / `login.microsoftonline.com` / a corporate identity provider page is the same mailbox reached through Outlook on the web to prime the OAuth token → Target Application "Exchange Online mailbox" plus a Configuration Question on the authentication method.
4. **OLEDB connection strings** → Excel workbooks (Target Application "Excel workbooks (via OLEDB)"); `Data Source=` names the file variable.
5. **`runApp` / `taskkill` executables** are the applications above; `taskkill` never creates a Target Application row on its own.
6. **Shared folders** (UNC paths in literals: `\\server\share\…`) → Platform Dependencies (a storage bucket or the kept network share), never a Target Application.
7. Global values `$@AAE_EmailSettings_*$` are Control Room email settings → Configuration Questions; `$@AABasePath$` is the runner's local repository root (migration path resolution) and disappears in UiPath.

## Call Graph Rules

1. Edge = enabled `TaskBot.runTask` whose `taskbotFile` resolves to a bot in the export. Order edges by editor line. A disabled `runTask` is a dead call (Source Map); an unresolved path is an external or deleted bot (Source Map, "unresolved").
2. Roots = bots never referenced by an enabled edge. Leaves = bots with no outgoing enabled edge. One root is the process entry; several roots in one folder are several processes or one process plus superseded copies — decide by the folder's other bots and the migration journal, flag `*[Inferred]*`.
3. Depth-first from the root; siblings in editor order; a `runTask` inside a loop or a condition inherits that step's rule ("for each pending record, invoke …", "when login fails, invoke …").
4. **The same sub-bot called from many places is one step of the callee's component and a reference in each caller's step**: a notification bot called eighteen times is one "Send notification" workflow; the callers' steps say which notification they send. Never one workflow step per call site.
5. Argument bindings: `taskbotInput` keys are the callee's `input` variables; a key bound to the same-named caller variable is state pass-through, a key bound to a literal or another variable is a real parameter (`vTempProcessName="AutoCompTo"`, `strDept="$StrCompanyCode$"`). `taskbotOutput` and the node's `returnTo` map (`{ExceptionReason: $ExceptionReason$, …}`) are the outputs the caller reads. The Interface of a library component lists the parameters the callers actually bind, not every flagged variable.
6. Recursion is impossible (a bot cannot run itself); a `times` loop around a `runTask` is a retry (Error Handling), not a call-graph cycle.
7. MetaBot logic bots call each other (`LoginLARA` → `GetWindowTitle`, `GetErrorPopupText`); these are edges inside the library component and become invoked workflows of the same library.

## Expression Translation

Conditions are structured, not expressions: `{variable} {operator} {value}` with `EqualsTo` / `EQ` = "is", `DoesNotEqualTo` = "is not", `INCLUDE` = "contains", `NOTINCLUDE` = "does not contain", `GreaterThan` / `GreaterThanOrEqualTo` / `LTE` = "exceeds" / "is at least" / "is at most", `matchCase: true` = "exactly". Several conditions on one `If` are joined by its `operator` (AND / OR). Variable transforms in values (`$x.String:toNumber$`) carry no business meaning; `$Loop-Files-1{extension}$ EqualsTo "xlsx"` reads "the file is an Excel workbook". String flags stored as text (`"TRUE"` / `"FALSE"` in STRING variables) are booleans. Translate with the table in [genome-format-guide.md § Business Rules](../genome-format-guide.md). The SQL in `sqlQuery` / `insertUpdateDelete` is a business filter or a write-back: translate `WHERE [Transport Status] IN ('Started','Sent','Generated')` as "whose transport status is Started, Sent or Generated"; keep column names as field names in the genome (they are the data schema, not code).

## UI Target Locators

Every `Recorder.capture` (and every capture used as a condition) carries its recognition data inline — there is no object repository in an Automation 360 export. `targets` decodes it into one normalized record per capture (`a360-targets.json`): `technology` (`JAVA`, `HTML`, `MS_ACTIVE_ACCESSIBILITY`, `MS_UI_AUTOMATION`), `controlType` (`TEXTBOX`, `PASSWORD_TEXT`, `BUTTON`, `LABEL`, `CLIENT`), `criteria` (only the properties the author **enabled** for matching, `name → value`, values may be variable expressions), `object` (the decoded blob: accessible `name`, numeric `role`, `description`, `className`, `id`, the accessibility `path` of child indexes, bounds, the recorder's `attributes` list), `window` (the resolved WINDOW variable: title, class, executable), `action`, `value` (redacted for password fields), `credential`, `screenshots` (the PNG names under `<Bot>Metadata/`), `line`, `disabled`. Keystroke commands and window operations are listed per bot with their window. Formats and per-property translation: [automation-anywhere-selectors-guide.md](automation-anywhere-selectors-guide.md). Extraction records only counts (captures per technology and control type, how many disabled, how many located by position only) in the Source Map; execution derives the catalog at migration preflight and turns it into Object Repository targets ([source-migration-guide.md](../source-migration-guide.md)).

Several captures usually target the **same control** (the recorder attached a fresh capture each time the author recaptured after a run-time error — the disabled twin sits one line above the live one): collapse by window + criteria + object name at execution ([source-migration-guide.md § Object Repository identity](../source-migration-guide.md)). A control whose only enabled criteria are `Path` / `Index` is positional (low confidence, live capture owed); one whose `Index` is a variable is a row of a grid (§ Composite actions).

## Evidence

Automation 360 bots log to a text file on almost every step (`LogToFile.logToFile` is 13% of all lines in a typical migrated export) and take a desktop screenshot in catch blocks and on business errors (`Screen.captureDesktop`, named `<Screen>Error_<timestamp>.png` under the process's `Screenshots` folder). That is the blanket evidence policy of [extraction-guide.md](../extraction-guide.md) Step 3: `profile` § EVIDENCE AND NOISE and `cards` report log and screenshot counts per bot — state the policy once per component (log lines become the robot's own logging at the same points; a screenshot per handled error becomes screenshot-on-failure attached to the job), never one activity per log line. `MessageBox` commands are the author's debugging (107 of 109 disabled in the reference export); an enabled `MessageBox` in a catch block blocks an unattended run and is an Error Handling finding, not evidence. Metadata PNGs are the recorder's captures of each control at design time: useful to an executor deriving a target (the screenshot shows the widget), never a run-time artifact.

**Checkpoints for the Source Map.** A process export asserts nothing formally; the checks it does make are business decisions (a popup text read and compared, a count queried) and belong to Business Rules. When a bot is a test (it only reads and compares), its GETPROPERTY-and-compare pairs are the checkpoints: record them as `line — asserts — expected — screenshot taken?`.

## Framework Pitfalls

1. **Disabled code is everywhere and looks like logic.** A fifth of all lines in a migrated export is disabled: whole `Step` blocks of the pre-migration Internet Explorer flow, the recapture twins of controls, the v11 credential comments, the IMAP connection commands replaced by OAuth. Read `dump --compact` (disabled subtrees folded) for the behaviour and the full dump only to understand history; put the superseded flow in the Source Map as dead code.
2. **Bot Migration plumbing is not behaviour.** Variables `m-string-start-in-path*` (a path staged for the next command), `M-Logic-Return-Dict-*` (a MetaBot's returned variables as a dictionary), `M-IsBotExecutedSuccessfully` and `M-Error-Description-Default-Val` (the `finally` / `throw` idiom marking the run Failed; the default value is empty), `Loop-Counter-*`, `Loop-Dataset-Column*`, `Loop-Files-*`, `Loop-Email-Response-*`, `Prompt-Assignment` (`Test-Value`), `my-list-variable`, the `.LegacyAutomation:parseVariableOperation` re-assignment after every assignment, `.LegacyAutomation:getAbsolutePath($@AABasePath$)` around every path. `profile` § MIGRATION PLUMBING counts them per bot. None of it enters the genome.
3. **Every variable is flagged input and output.** Migrated task bots declare 50–90 in/out variables and pass them all on every `runTask`; the real interface is the handful the callee reads or writes. Derive it from the body and from the bindings that carry a literal or a differently named variable.
4. **Empty error text means success.** Sub-bots return an error reason built from `Error-Description`, whose migration default is empty; a caller that tests the returned text for a word (`INCLUDE "Completed"`) can never see it and takes the failure branch. Carry the caller's rule as written, flag it `*[Inferred]*` as a suspected defect, and word the intended behaviour ("an empty error reason means the update succeeded").
5. **N identical branches per runner.** A `BOT_SCALE_SEQUENCE`-style switch repeats a 300-line block per bot runner, differing only in the credential and in accidental drift (one branch reads all mail instead of unread mail, one parses the company code with an extra step, one moves mail without filtering by subject and sender). Extract one step with the account as a parameter and list the drift as source quirks.
6. **`taskkill` is cleanup, not an application.** Migrated bots force-close Java, Edge, Excel and Outlook before and after work; word it once under Error Handling / cleanup.
7. **Positional Java locators.** Oracle Forms controls are matched by accessibility `Path` (`1|1|2|1|1|1|1|1|1|3|1|1|1|1|1|5`) and `Index`; the same control appears with `-1|…` and `1|…` paths in its recaptured twins and identical `Name`s repeat per grid row. `Name` + `Role` are the reusable identity; `Path` / `Index` are position ([automation-anywhere-selectors-guide.md § Java](automation-anywhere-selectors-guide.md)).
8. **Window variables are snapshots.** A WINDOW variable records the handle, size and the Java runtime's executable path of the capture session (`jre1.8.0_281`, `jre7`, `jre1.8.0_331` across bots); only title wildcard, class and executable *name* carry over. Titles differ by browser generation (`LARA*` for the applet frame, `LARA*- Microsoft Edge` for the launch tab, `fulfillmentSCE` for the login frame).
9. **Plaintext secrets.** A literal typed into a password field or assigned into a password-named variable (`StrLaraPassword`) is a secret in the export. The inventory script redacts the value wherever it appears; the genome names the credential asset and the report says the export contains a plaintext password without repeating it. Test recipient addresses and a runner's personal user name in disabled test commands are personal data — configuration values, not defaults to keep.
10. **Sheet names read through a formula.** `SetCell` `=MID(CELL("filename",A2),…)` into a spare cell followed by `GetSingleCell` is the v11 idiom for "read the active sheet's name"; it also **writes into the customer's input file** (cell M2). Word the intent (find the sheet whose name contains `TO_STATUS_REP`) and note the side effect.
11. **Excel through OLEDB.** `Database.*` commands with an ACE OLEDB connection string are workbook reads and writes; `[Sheet$]` is a sheet, the SQL is the filter or the write-back. `dosaveData` on `disconnect` is meaningless for a workbook. IMEX and HDR flags in the connection string are Configuration Question material (`CONNECTIONSTRING` itself is a config value with a `FileName` placeholder).
12. **`continueOnError` plus a string flag.** Callers run sub-bots with `continueOnError: true` and then test a `blnIsTaskError` string (`"TRUE"`) the sub-bot set, calling a shared exception logger and `stopTask`. That is the process's exception routing: one Error Handling § Global entry, not a rule per call site.
13. **Comments drift.** Section comments (`START: Email processing.`, `END: Download Attachment File`) are copy-pasted around unrelated calls; log messages are the reliable narration. Descriptions of MetaBot logics ("Metabot logic to …") are accurate.
14. **The launch page and the application are different windows and technologies.** A browser tab (HTML: click the `LARA` button in the `mainFrame` frame) starts a Java Web Start applet (JAVA: everything after); Java's own dialogs (`Security Warning`, `Java Update Needed`) are Win32 (MSAA) windows of `javaw.exe` / `jp2launcher.exe`; Edge's toolbar is UI Automation. One business step (open LARA) spans four technologies and three windows — the Target Applications table names the application once, the selectors guide maps each technology.
