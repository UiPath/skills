# Selector Translation — SAP GUI

SAP GUI's side of [selector-translation-guide.md](selector-translation-guide.md): the SAP session attributes of `wnd`, the `sap` tag, and what rules 8 and 9 add, for SAP GUI for Windows and SAP GUI for Java. Read whole with that guide when the target catalog holds SAP GUI controls; rule numbers are its own.

## `wnd` — SAP session attributes

| Attribute | Meaning | Tier / role |
|---|---|---|
| `sapSysSessionId` | server-side SAP session id, carried by the session window **and** by every SAP modal dialog of that session; absent on the SAP Logon pad | session — its value is runtime, so a selector uses it only as "present" (`sapSysSessionId='?*'`), which separates SAP dialogs from other `#32770` windows of `saplogon.exe` |
| `sapSysName`, `sapClient`, `sapUser`, `sapLanguage`, `sapTransaction`, `sapProgram`, `sapScreen`, `sapWindowName` (`wnd[0]`, `wnd[1]`), `sapGuiSessionId` (`/app/con[0]/ses[0]`), `sapSession`, `sapSysNumber` | SAP GUI session context; `sapScreen`, `sapSession`, `sapSysNumber` are numbers (`sapScreen='0100'` matches screen 100) | session — matched; `sapTransaction`, `sapProgram` and `sapScreen` change with every screen, as `title` does |
| `sapReadyState` | whether the session is idle | runtime — readable through Get Attribute; a selector that names it does not parse |

## `sap` — SAP GUI scripting element

| Attribute | Meaning | Tier / role |
|---|---|---|
| `id` | normalized scripting id: everything after `wnd[n]/` — `usr/ctxtRF02D-KUNNR`, `tbar[1]/btn[8]`, `usr/cntlGRID1/shellcont/shell`. `/app/con[0]/ses[0]/` and the `wnd[n]/` segment are stripped, so a control in a modal dialog has the same `id` as its main-window twin; the window element tells them apart. `usr/` stays: an id with `wnd[n]/` left on, with `usr/` cut, or reduced to the control's own last segment matches nothing. The driver's default target for any activity type is this `id` alone, strict | very reliable — plain, case-sensitive text resolves in one scripting call (`FindById`); a wildcard, a regex/fuzzy matching mode or `casesensitive:id='false'` moves the search onto a per-node tree walk with no node cap and no timeout of its own. In an `id`, `*` and `?` match within one `/`-separated segment and never cross a `/`: `id='*/okcd'`, `id='tbar[0]/ok*'` and `id='usr/*/*/*/*/shell'` resolve, `id='*okcd'` and `id='usr/*/shellcont[0]/shell'` do not, and a segment wildcard can resolve to whichever node first fills the pattern (`id='usr/cntlIMAGE_CONTAINER/*'` resolves the container's first child). A field found by its technical name at any depth is therefore the regex form `id='.*<prefix><FIELD>' matching:id='regex' type='Gui…'`, `[` and `]` in the tail escaped as `\[` `\]`. A backslash in an id (`tabpT\01`) stays literal under segment wildcards (`usr/*/tabpT\01`); in the regex form it is an escape, so it is doubled there (`id='.*tabpT\\01' matching:id='regex'`), and a single one fails to parse |
| `leafid` | the `id`'s last segment: type prefix, name, array suffix (`ctxtRF02D-KUNNR`, `okcd`, `btn[8]`) | identity — matched at run time at any depth below the preceding tag, over the same tree walk as a wildcard `id`, so a leaf several nodes share (`shell`, `shellcont`) resolves to the shallowest of them; never beside `id`, which fails the search. The driver never generates it |
| `type` | SAP component type name (`GuiCTextField`, `GuiButton`, `GuiTableControl`); the driver names the ALV grid and tree `GuiGridView` and `GuiTree`, and their parts `GuiGridViewCell`, `GuiGridViewRow`, `GuiGridViewColumn`, `GuiTreeNode`, `GuiTreeItem`. Case-sensitive, and the case is the front end's: SAP GUI for Windows reports the scripting API's names (`GuiOkCodeField`, `GuiStatusbar`, `GuiTitlebar`), SAP GUI for Java its own (`GuiOKCodeField`, `GuiStatusBar`, `GuiTitleBar`), so a type recorded on one front end matches nothing on the other. A plain-text `id` resolves without it | structure — narrows a walk cheaply, on the elements that take it (table below) |
| `text` | the `Text` property, untrimmed (SAP pads some captions with spaces — match with trailing `*`); a grid cell reports its cell value | text — purpose-constrained; beside a column attribute (`tableCol`, `colName`, `colTooltip`) and without `tableRow`, it finds the first cell of that column holding the value: a row by content |
| `tooltip` | `Tooltip`, falling back to accessibility tooltip, then default quick-info; untrimmed. On input fields the quick-info usually carries the field label | semantic |
| `tableRow` | 0-based **absolute** row of a table control or ALV grid (not visible-relative; addressing may scroll) | table — alone, the row element |
| `tableCol` | 0-based **absolute** column of a classic `GuiTableControl` (not the displayed one) | table — alone, the column element; with `tableRow`, the cell. `tableRow='-1' tableCol='-1'` is the all-items element (the table's top-left corner) on a table control and on an ALV grid alike; on an ALV grid that pair is the only `tableCol` accepted, and any other rejects the selector, since grid columns are `colName` or `colTooltip`. Either attribute may carry a selector variable (registering one: the invoked RPA owner's number-attribute variable guidance) |
| `colName` | on an ALV grid, the **technical** column name (`MATNR`), language-stable; on a classic `GuiTableControl`, the column's displayed title (`Depart.city`), in the logon language | table — alone, the column element (the grid's header, the table's column); with `tableRow`, the cell: `id` of the grid + `tableRow` + `colName` is the driver's default for an ALV cell |
| `colTooltip` | the column's tooltip — its `Tooltip`, falling back to the accessibility tooltip, then the default quick-info — trimmed; on a classic table control and on an ALV grid alike it is **not** the header's displayed title: a column headed `G/L acct` has `colTooltip='G/L Account'`, one headed `Tax code` has `'Tax Code'` | table — with `tableRow`, a cell of either kind; alone, the column element of a table control only (an ALV grid rejects it without `tableRow` or `text`). The driver's default classic cell is `id` of the table + `tableRow` + `colTooltip`, a tooltip text in the logon language; `tableCol` is the language-independent form. A classic cell is never addressed by its own scripting id (`…/tbl<TABLE>/<prefix><FIELD>[c,r]`): the id resolves at run time as well, exact or as a regex (a slower tree walk), but its `[c,r]` count only the displayed rows and columns, and they equal `tableCol='c' tableRow='r'` only while the table shows its first row and column |
| `relpath` | tree node path of node **display texts**, root-relative, slash-separated, literal `/` escaped as `\/` (`Root/Child/Leaf`) | semantic — the value the Expand Tree activity takes |
| `itemId` | tree item inside a node: index (`0`…`n`) for list trees, column name for column trees | identity — trees only |
| `idx` | | position |

Which of these a tag carries depends on the element it resolves to. `id`, or `leafid` in its place, finds the control; on a table control, ALV grid or tree every other attribute addresses an element inside the control. An attribute the element does not take fails the search; it is never skipped.

| Element | Its tag carries, besides `idx` |
|---|---|
| Table control, ALV grid or tree itself | `id` alone: `type='GuiGridView'` beside the grid's id finds nothing |
| Row, column, cell or all-items element of a table control or ALV grid | the control's `id` with only `tableRow`, `tableCol`, `colName`, `colTooltip`, `text`, in the combinations their rows above give |
| Tree node | the tree's `id` and `relpath` |
| Tree item | `itemId` alone, in a tag after its node's tag |
| Any other control: field, button, label, container | `id`, `text`, `tooltip`, `type` |

The attribute table above is the whole `<sap>` schema. `name` (the technical field name), `labeledby` (the field's label), `label`, `iconName`, status and scroll attributes are readable through Get Attribute only: a selector that names one does not parse. A combo box's `items` and `selecteditem` are the entries' captions; no key is exposed, so a source that chose an entry by key needs the caption in the logon language. A matching `id` requires the search to start from the right window: modal dialogs are their own `<wnd>` (`cls='#32770'`), and `usr/…` resolves inside whichever window the chain names. System-toolbar ids are fixed by function key: `tbar[0]/btn[11]` is Save on every screen that offers it, SAP GUI for Windows leaves a button the screen does not offer out of the tree, and a caption can change (`btn[15]` is Log Off on SAP Easy Access, Exit elsewhere); application-toolbar buttons and menu positions (`mbar/menu[4]/menu[2]`) shift between screens: drive them with the SAP activities (Click Toolbar Button, Select Menu Item, Call Transaction), not with selectors, when the tooltip or menu text is known, and otherwise target the id on the screen the source pressed it on, flagged `positional`. Select Menu Item's item is the menu path in captions, as the session window's `items` list it (`System/Status...`). A row found by content in a table control or ALV grid is the SAP Table Cell Scope activity, whose row filter is a cell selector of this catalog (`text` beside a column attribute); its row modes and limits are the package's own (its activity doc and SAP guide). ALV grid ids are unreliable across sessions; the driver itself prefers the grid's technical column names — a grid cell target is `<sap id='<grid id>' tableRow='…' colName='…' />` and stays **medium** until seen live. A **classic list** (an ALV list, a report's output) has no table element and takes no table attribute. Each cell is a `GuiLabel` `usr/lbl[<character column>,<line>]` and a row check box `usr/chk[<column>,<line>]`, where the line counts the displayed list page and the other cells of a row share its line. A row found by content is the column's label pinned by its value, `<sap id='usr/lbl[<column>,*]' text='<value>' />`, the `*` staying inside its segment. The driver's own default for a list label is its `text` plus `type`, which rule 4 excludes on a read target.

## Rule 8 — SAP GUI

The column comes from the header caption: on a SAP GUI table control the recorded title itself as `colName`, and on an ALV grid `colTooltip` — the column's tooltip, not the title its header displays, so a recorded title is checked against a live listing before it becomes one (the grid's `colName` is the technical field name; § `sap`). SAP GUI rows are 0-based and absolute, so a source's 1-based visible row number is neither; a SAP GUI row found by content is `text` beside the column attribute (§ `sap`).

## Rule 9 — SAP GUI

A SAP session window is identified by `app` and `cls` alone — its title is the current screen's and changes with every transaction; a SAP modal dialog by `cls='#32770'`, the presence of `sapSysSessionId` (which the SAP Logon pad and the process's other `#32770` windows lack) and its caption — without a recorded caption, by the first two alone, which match whichever SAP dialog of the session is open, and its own `sapProgram` and `sapScreen` (the popup's program and screen number, which a source recording `<PROGRAM>:<DYNPRO>` names) tell one popup from another. The other `sap*` session attributes: § `wnd`.

| Technology | Scope on | Shape |
|---|---|---|
| SAP GUI session / SAP modal dialog | `app` + `cls` / `app` + `cls` + `sapSysSessionId` present + caption, or the popup's program and screen in its place | `<wnd app='saplogon.exe' cls='SAP_FRONTEND_SESSION' />` / `<wnd app='saplogon.exe' cls='#32770' sapSysSessionId='?*' title='Information' />`, `<wnd app='saplogon.exe' cls='#32770' sapSysSessionId='?*' sapProgram='SAPLSHSY' sapScreen='0700' />` |
