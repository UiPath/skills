# UiPath Genome — document, author, and execute automation blueprints

Genome: markdown specification an AI agent consumes to rebuild an automation — what it does, business rules, data moving between parts, platform resources, its transactional shape, verification, and which UiPath skill builds each part. Genomes stay thin: build skills carry UiPath know-how; a genome describes *what*, skills know *how*.

> **Read the referenced guide in full before acting.** This file routes; guides carry the rules, each subject in exactly one guide. Open the guide for the detected mode and the format guide, and read each whole file — do not grep them or work from memory. Exception: the two **catalogs** — [selector-translation-guide.md § Tag attribute catalog](references/selector-translation-guide.md) and a framework selectors guide's per-technology tables — are read by section: list headings, then read the sections for the technologies the source recorded; the rules around them are read whole.

## When to Use This Skill

- Existing UiPath project or solution to document, understand, or prepare for migration ("what does this solution do", "extract a genome", "document this process at high and low level")
- Described automation idea needing a specification before building
- `*-genome.md` file to build from
- Existing genome to update, split into components, or re-extract after source changed

## Mode Detection

Determine mode from input, in this order:

1. **`*-genome.md` path plus build intent** ("build", "execute", "implement", "follow") → **Execute**. Read [execution-guide.md](references/execution-guide.md).
2. **Directory, project file, solution manifest, or another framework's export** (`project.json`, `project.uiproj`, `.uipx`, `.flow`, `.bpmn`, `agent.json`, `Workflow.json`, `caseplan.json`, `uipath.json`; or a folder with none of these holding another automation or test framework's export) → **Extract**. Read [extraction-guide.md](references/extraction-guide.md) and the framework's guides (§ Source Frameworks).
3. **Description, idea, SOP, or process narrative** with no source project → **Author**. Read [authoring-guide.md](references/authoring-guide.md).
4. **`*-genome.md` path plus edit intent** ("update", "add a step", "split", "remove the inferred flags") → **Edit** in place per the edit tables in the authoring guide (Step 8) and, for an extracted genome, the extraction guide (Step 7); re-extract instead when the user says the source changed.

A PDD or SDD, or a request to design a solution and derive tasks, is `uipath-planner`'s job, not a genome. Say so and stop.

Every mode reads [genome-format-guide.md](references/genome-format-guide.md) for content rules and [skill-mapping-guide.md](references/skill-mapping-guide.md) for Build With.

## Source Frameworks

A UiPath source (`.uipx`, `project.json`, `project.uiproj`, `.xaml`/`.cs`, `.flow`, `.bpmn`, `caseplan.json`, `agent.json`, `Workflow.json`, `uipath.json`) is read with [uipath-source-guide.md](references/uipath-source-guide.md); its UI targets are carried over, not translated (that guide's § UI Target Locators). Every other framework is read through the **framework migration pack** maintained outside this plugin, which holds per framework a **source guide** (detection, inventory, signals, component → skill mapping, composite actions, UI target locators, test data, evidence), a **selectors guide** (locator formats, attribute-by-attribute translation into UiPath targets) and an **inventory script**. Resolve it once per run, in both modes:

1. **Ask for its location.** Ask "Where is the framework migration guide?" unless the request, or the execution scaffolding answer ([execution-guide.md § 1.3](references/execution-guide.md)), already gave it. Accept a folder path (`<PACK_DIR>`); a git URL is cloned into a scratch folder first. Never search the disk for it, never work from memory of its contents, never copy its files into this skill or beside a genome.
2. **Select the framework row** in `<PACK_DIR>/README.md` § Frameworks: the row whose detection signals match the given files (Extract), or the framework the Source Map names (Execute). An extracted genome names its framework in the Source Map; that name selects the row and makes the execution a **migration**.
3. **Run, then read.** Run the row's script before reading any export file. Extract reads `<PACK_DIR>/<framework>/source-guide.md` in full and writes the genome and its Source Map. Execute derives the catalogs with the same script ([source-migration-guide.md § Migration preflight](references/source-migration-guide.md)) and reads the source guide's § Composite actions and `<PACK_DIR>/<framework>/selectors-guide.md` by technology section together with [selector-translation-guide.md](references/selector-translation-guide.md).

No row matches → say which framework the files appear to come from and that the pack has no guide for it; never improvise an extraction. Pack not available → Extract stops (no genome is extracted from a framework nobody has read); Execute continues without the migration part — live capture or placeholders, stated in the report ([source-migration-guide.md § Migration preflight](references/source-migration-guide.md) step 1). Adding a framework: `<PACK_DIR>/CONTRACT.md`; nothing in this skill changes.

## Critical Rules

Each rule names its subject and the one guide that states it in full; the guide's wording is the rule.

1. **Choose the genome level before writing** — one project is a component genome, two or more (or a coordinator plus what it invokes) a process genome with one component genome per project, and test components are folders of one test project: [genome-format-guide.md § Two Levels](references/genome-format-guide.md).
2. **Read the source, do not ask about it.** Extraction reads every non-generated file and never asks what the automation does, only for resources beside it, which it reads and links: [extraction-guide.md](references/extraction-guide.md) Steps 1 and 3.
3. **Infer complexity, never ask for it**, defaulting lower when ambiguous: [genome-format-guide.md § Complexity](references/genome-format-guide.md).
4. **Replication-grade detail in behavioural wording**, with activity names, variable names, file paths and code syntax banned from the body: [genome-format-guide.md § Workflow](references/genome-format-guide.md) and § Provenance.
5. **Generalize hardcoded values into Configuration Questions** with the source value as default: [genome-format-guide.md § Configuration Questions](references/genome-format-guide.md).
6. **Every section present, always**, stub lines for sections that do not apply: [genome-format-guide.md § Stub Lines](references/genome-format-guide.md).
7. **One skill per Build With row, from the mapping guide only**; operate-only skills belong under Platform Dependencies: [skill-mapping-guide.md](references/skill-mapping-guide.md).
8. **Preamble and blueprint blockquote are mandatory**, and Build With (or Components) precedes Workflow (or Process Map) so an agent builds instead of executing the steps: [genome-format-guide.md § Two Levels](references/genome-format-guide.md) rule 5.
9. **Acceptance criteria are specific and testable**; "completes successfully" and "handles errors" are banned: [genome-format-guide.md § Acceptance Criteria](references/genome-format-guide.md).
10. **Flag ambiguity, never leave gaps**: best interpretation plus `*[Inferred]*`, uncertainty recorded in the Source Map: [genome-format-guide.md § Ambiguity Marker](references/genome-format-guide.md).
11. **Write immediately, offer edits after**; edits are in place, never a regeneration: [genome-format-guide.md § Write, Then Offer Edits](references/genome-format-guide.md).
12. **Execution never edits the genome and never skips the configuration questions** — the genome's own and the scaffolding questions per project, waived only by an explicit "take the defaults" in the current request — then advances group by group without pausing and assesses every acceptance criterion: [execution-guide.md](references/execution-guide.md) § 1.3, § 2.2, § 3.
13. **Extraction writes genomes only, and the Source Map is the migration contract** — framework, export path and identity, per-step source objects with ids, checkpoints, counts; locators and rows stay in the export: [genome-format-guide.md § Source Map](references/genome-format-guide.md).
14. **Execution on an extracted genome is a migration by default** — catalogs derived from the export at preflight, every UI activity given an `INFERRED (<confidence>)` Object Repository target with the first live run as healing pass, test data filled from the data catalog, one credential asset per account and no secret ever copied: [source-migration-guide.md](references/source-migration-guide.md).
15. **Build through the owning skill, verifiably** — its mandatory reads; for every activity kind the build uses, the default XAML (the shape) and the package's per-activity doc (the property and its value encoding), fetched before the first file using it is written; workflows authored as files, not generated; subagents under the same obligation: [execution-guide.md § 2.2](references/execution-guide.md).
16. **Composite source actions are contracts in the genome and patterns at build** — the substep carries what is typed, how the entry is matched, which key confirms, the path levels, the row rule ([genome-format-guide.md § Workflow](references/genome-format-guide.md)); execution expands each into its pattern with a verify sub-step, never the nearest single activity ([source-migration-guide.md § Composite interactions](references/source-migration-guide.md)).
17. **UiPath selector truth lives in one guide** — tag chain by technology, one tag is one node, node-dependent `aaname`, one application one scope, the tag comes from the strongest evidence (recorded markup over a known node role over the control type), no borrowed identifier, widget anatomy: [selector-translation-guide.md](references/selector-translation-guide.md) rules 1–16. **Verification is a property of the acting activity** (`VerifyOptions` observing the element that shows the outcome; a Check activity only for a genuine branch): [source-migration-guide.md § Verification](references/source-migration-guide.md).
18. **A migrated target carries a verdict, and `offline-unverified` is one** — `verified` against the target application, `shape-verified` against a comparable instance of the same product, `offline-unverified` when nothing is reachable, per interaction family: [source-migration-guide.md § Verifying targets](references/source-migration-guide.md). A reachable application is a windfall, never a precondition for finishing the run. The skill ships no checker; the mechanically checkable rules and why no script is maintained: [selector-translation-guide.md § Checking a definition](references/selector-translation-guide.md).
19. **Most source steps are not UI activities** — waits, assertions, stores, labels, jumps, comments, log lines and engine settings become verification, reads, structure, a log message or nothing at all, and linking is the last thing done to a workflow file: [source-migration-guide.md § Source steps that are not UI actions](references/source-migration-guide.md) and § UI targets.
20. **The transactional shape is described in the genome and split at build.** Every genome carries a Transactional Shape — one block per flow (one kind of item handed from its producer to its consumer: components 1 → 2, 2 → 3, an independent 5 → 6; an item's children are levels of its flow, not a flow), each with the unit of work and its alternatives, the as-is roles, store and coordination, the per-item outcomes, the split options for the unit and for each alternative unit — A one process without a queue, B a producer process and a consumer process, C one process with a queue — with what each requires and changes, and the evidence — or its stub; it asserts no split, no store, no template and no unit. Execution asks the split questions per flow (unit, split option, producers, consumers, store, template, shared steps, triggers) with defaults prepared from the genome, may materialise one component as several projects or two components as one, resolves each component across its flows, and records the choice; the behaviour is owed whatever the choice: [genome-format-guide.md § Transactional Shape](references/genome-format-guide.md); [execution-guide.md § 1.3, § 1.4, § 2.2](references/execution-guide.md).
21. **Source values are read from the source, not from their rendering** — comparison literals and case rules verbatim, counts, lengths, occurrences, waits and control-flow flags; an empty rendering is "not shown", never "not set". Extraction writes them so ([extraction-guide.md](references/extraction-guide.md) Step 3); execution checks every one the genome cites before a group builds on it and follows the source where they disagree ([source-migration-guide.md § Migration preflight](references/source-migration-guide.md) step 4). A scripting wrapper's verbs are the caller's UI steps on the elements its identities name, never a library of verbs.
22. **A suspected source defect is verified before it is written: first in the full rendering, then in the framework's source itself.** The inventory output is the pack's rendering, not the source. Each finding is read in the export with a generic reader that keeps every key, and is classified as a rendering artefact (reported for the pack), a source defect, a source rule, or unresolved platform semantics. It is then written in that form, with its evidence in the Source Map ([extraction-guide.md](references/extraction-guide.md) Step 4b; marker: [genome-format-guide.md § Source Defects](references/genome-format-guide.md)).

## Workflows

### Extract (project or solution → genome)

Detect framework and deployment unit → ask for related resources → inventory → extract signals with the source guide's tables → build call and handoff graphs → verify every suspected source defect in the full rendering and in the framework's source → infer complexity → map signals to sections (process genome first, then components; the Transactional Shape from the source's per-item constructs) → complete the Source Map as the migration contract and check it resolves with `scripts/genome-step-map.py` → write, then offer edits. Full procedure: [extraction-guide.md](references/extraction-guide.md); framework guides and scripts: § Source Frameworks.

### Author (description → genome)

Receive → choose level → infer complexity → extract → suggest platform capabilities and describe the transactional shape (as-is, split options per unit of work, evidence) → bounded follow-ups (simple 0-1, medium 1-2, complex 2-3 rounds, all questions of a round in one message) → generate → write → offer edits. Full procedure: [authoring-guide.md](references/authoring-guide.md).

### Execute (genome → automation)

Parse and validate the genome → preflight discovery → ask every configuration question (genome, then the split questions per flow, then scaffolding per resulting project) → resolve one project or one solution (libraries pack first; each consumer project on the REFramework template when chosen; a split may materialise one component as several projects) → plan skill groups → build each group through the owning skill → on an extracted genome, migrate UI targets and test data from the export → wire handoffs → assess every acceptance criterion → report. Full procedure: [execution-guide.md](references/execution-guide.md); target and data migration: [source-migration-guide.md](references/source-migration-guide.md).

## Anti-patterns

Each is prohibited in full where its subject lives; this list only routes.

1. **Asking the user what the project does or which complexity it is**; previewing before writing; code, file paths or activity names in the body; Integration Service treated as an application; compressed steps or disconnected rules and handlers — [genome-format-guide.md](references/genome-format-guide.md) and [extraction-guide.md § Anti-patterns](references/extraction-guide.md).
2. **Producing a genome when the user brought a PDD/SDD or asked for a solution design.** That is `uipath-planner` (§ Mode Detection).
3. **Retired skill names in Build With** (`uipath-rpa-workflows`, `uipath-coded-workflows`, `uipath-coded-agents`); a stale name will not resolve at execution — [skill-mapping-guide.md](references/skill-mapping-guide.md) rule 5.
4. **A process genome without Handoffs, or a component Interface that disagrees with Handoffs** — [genome-format-guide.md § Handoffs](references/genome-format-guide.md).
5. **Building before configuration answers exist, stopping between execution groups, or generating workflows by script** — [execution-guide.md § Anti-patterns](references/execution-guide.md).
6. **A Source Map without the export's location or per-step source objects, or catalogs copied beside the genome** — [genome-format-guide.md § Source Map](references/genome-format-guide.md).
7. **Placeholder targets, generated rows, copied passwords, naive composite translation, per-step Object Repository entries, Check activities instead of `VerifyOptions`, targets reported done with no verdict, a linked workflow rewritten wholesale instead of edited** — [source-migration-guide.md § Anti-patterns](references/source-migration-guide.md).
8. **Merged widget nodes, invented identifiers, `DIV` as a default tag, per-screen scopes, assumed grid markup** — [selector-translation-guide.md](references/selector-translation-guide.md) rules 8, 9, 13, 14.
9. **A split, a store or a verdict asserted in the genome; a producer folded into the consumer's initialisation outside option C, or under C without a once-guard; a source's coordination queues carried by habit; a state machine around a linear flow; framework plumbing transcribed as steps; or a split question skipped** — [genome-format-guide.md § Transactional Shape](references/genome-format-guide.md); [execution-guide.md § Anti-patterns](references/execution-guide.md) 10; [extraction-guide.md § Anti-patterns](references/extraction-guide.md) 12–13.
10. **A source defect written from a rendering, or a rendering artefact written as a source defect** — [extraction-guide.md](references/extraction-guide.md) Step 4b and § Anti-patterns 16.
