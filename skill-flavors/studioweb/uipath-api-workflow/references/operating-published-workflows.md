After publication, operate and diagnose the API Workflow through capabilities exposed by Studio Web. Inspect each live lifecycle, run, job, log, trace, trigger, or connection tool schema immediately before invocation and use exactly its declared fields.

- Use read-only embedded `uip is` discovery, including `connections list` / `ping`, to inspect connector and connection state.
- Use the actual Studio Web tool result and, when relevant, the visible run or job state as operational evidence.
- Preserve explicit consent before every operation that starts a workflow or can create external side effects.
- For an unavailable published operation or diagnostic, report the exact capability gap and hand off the deeper platform investigation.
- Treat host-intercepted `uip solution publish` as the separate, approved flow for publishing a new active-solution version.
