## Studio Web Command Scope

**The `uip codedapp` CLI tool is not available in Studio Web.** The browser bundle does not ship it and the host intercepts none of its verbs, so `init`, `push`, `pull`, `pack`, `publish` and `deploy` all fail here. Neither is there npm, `create-vite`, a dev server or a full Node.js runtime to scaffold, install, build or run the React app: the shell's `node` / `js-exec` is a QuickJS sandbox for small scripts over files in `/solution` and `/tmp`, not a Node.js toolchain.

A coded app here is always an in-solution AppV2 project. If the open solution has no AppV2 project for this app, create it before scaffolding with the `CreateProjects` host tool: `projectName` = the app name, project type `AppV2`, `projectSubType` `Coded` for a Coded Web App or `CodedAction` for a Coded Action App. When the request does not say which, ask first (Critical Rule 1). If the user already created the project, use it. Read the project name from the tool result and write the app's sources under `/solution/<ProjectName>/source/`; the build writes its bundle to `source/dist/`. The host writes `project.uiproj` and `webAppManifest.json` and registers the app as a solution resource, so do not create those two files yourself.

Everything else in this skill applies. Read and edit the app's files directly — React/TypeScript source, `package.json`, `uipath.json`, `webAppManifest.json`, OAuth scopes and SDK usage — following the authoring rules below. Scaffold by writing files, as [create-web-app.md](references/create-web-app.md) Step 3.2 and [create-action-app.md](references/create-action-app.md) § Project Scaffolding list them. Nothing compiles the app in Studio Web: its first build runs later from `source/` with no lock file (`npm install`, then `npm run build`, which is `tsc -b && vite build`), so write every config file that build needs and keep every import type-correct. Do not run install, build, run, pack, publish or deploy commands, and do not report the app as built, run or deployed. Diagnosing a deployed failure works from the project files plus the families that *are* bundled (`uip or`, `uip traces`).

The CLI host's steps below do not apply here, with these replacements:

- **Critical Rules 3 and 20, the Two lifecycles callout and the Completion Output's next steps** describe the CLI host (`npm run build`, `create-vite`, `uip codedapp init`, `npm run dev`). Scaffold by writing files instead, and check them against [web-app-template.md](assets/templates/web-app-template.md) § Build checklist before handing the app over.
- **Critical Rule 19:** no `node_modules` exists here. When the host can fetch URLs, read a service's types from the published package at `https://unpkg.com/@uipath/uipath-typescript@<VERSION>/dist/<SUBPATH>/index.d.ts`, with `<VERSION>` from `package.json`. Otherwise use only the calls the template and `references/sdk/*.md` show, and tell the user which SDK calls you could not verify.
- **`npm install <package>` in any step:** add the package to `package.json` instead. Keep the version the step pins (`<package>@x.y.z` or `--save-exact`); otherwise use `"latest"`.
